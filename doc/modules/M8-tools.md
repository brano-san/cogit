### T8.8 · Create Pull Request через браузер

Никакой авторизации у провайдеров внутри приложения: Cogit открывает системный браузер
на готовой форме.

- [x] Определение провайдера по URL remote: GitHub, GitLab, Bitbucket, иначе — пункт скрыт
- [x] Сборка URL с ветками и предзаполненным заголовком из последнего коммита:
      - GitHub — `/compare/<base>...<head>?expand=1&title=…`
      - GitLab — `/-/merge_requests/new?merge_request[source_branch]=…`
      - Bitbucket — `/pull-requests/new?source=…&dest=…`
- [x] Открытие через `tauri-plugin-opener`
- [x] Если ветка ещё не отправлена — сначала предложить push, иначе форма откроется пустой
- [x] Ссылку можно скопировать вместо открытия

**DoD:** на репозитории GitHub кнопка открывает форму с уже выбранными ветками
и заголовком.

**Ограничение.** Формат URL — не публичный контракт провайдера и может измениться.
Поэтому шаблоны лежат данными рядом с пресетами хуков ([M10](M10-hooks.md)), а не зашиты
в код, и неизвестный хост просто скрывает пункт меню вместо того, чтобы вести в никуда.

## Известные ловушки

| Ловушка | Последствие | Как избежать |
|---|---|---|
| Blame через CLI на каждое открытие файла | Секунды ожидания | `gix` с фичей `blame` и кэшем на файл |
| Палитра без учёта контекста | Действия падают при исполнении | Проверка применимости до показа |
| Настройки, требующие перезапуска без предупреждения | Пользователь думает, что не сработало | Явная пометка в интерфейсе |
| Игнорирование `.mailmap` | Один человек в списке авторов дважды | Учитывать при чтении |
| Восстановление сессии с удалённым репозиторием | Ошибка при старте | Пропускать недоступные пути с уведомлением |
