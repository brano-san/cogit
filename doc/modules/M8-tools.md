Показывать недоступные действия с пояснением важнее, чем прятать их: пользователь должен
понимать, почему нужного пункта нет.

### T8.2 · Find Object (`Ctrl+P`)

**DoD:** поиск по репозиторию на 50 000 коммитов отвечает быстрее 300 мс.

### T8.3 · Git Blame (`Ctrl+Shift+L`)
- [ ] Аннотация файла через `gix` (фича `blame`)
- [ ] Колонка слева: автор, дата, короткий хеш
- [ ] Группировка соседних строк одного коммита
- [ ] Клик по аннотации показывает коммит в графе
- [ ] Переход к состоянию файла до этого коммита
- [ ] Учёт `.mailmap`
- [ ] Игнорирование коммитов из `.git-blame-ignore-revs`

**DoD:** blame файла на 5 000 строк с историей в 1 000 коммитов считается быстрее 2 секунд.

Поддержка `.git-blame-ignore-revs` обязательна: без неё blame в проекте, пережившем
массовое форматирование, бесполезен.

## Приёмка модуля

- [ ] Палитра находит все действия

- [ ] Настройки применяются без перезапуска
- [ ] Сессия восстанавливается

## Известные ловушки

| Ловушка | Последствие | Как избежать |
|---|---|---|
| Blame через CLI на каждое открытие файла | Секунды ожидания | `gix` с фичей `blame` и кэшем на файл |
| Палитра без учёта контекста | Действия падают при исполнении | Проверка применимости до показа |
| Настройки, требующие перезапуска без предупреждения | Пользователь думает, что не сработало | Явная пометка в интерфейсе |
| Игнорирование `.mailmap` | Один человек в списке авторов дважды | Учитывать при чтении |
| Восстановление сессии с удалённым репозиторием | Ошибка при старте | Пропускать недоступные пути с уведомлением |
