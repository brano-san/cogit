# M12 · Хирургия коммитов: Split-Off и Rollback-To

**Статус:** `TODO` · **Веха:** E · **Зависит от:** M1, M4, M6

Две операции над уже сделанными коммитами. Разные по риску настолько, что их стоит
рассматривать вместе только чтобы не перепутать.

## T12.1 · Rollback-To — безопасная

Вернуть содержимое файла или всего рабочего каталога к состоянию выбранного коммита,
**не двигая HEAD**.

```sh
git restore --source=<oid> -- <path>     # один файл
git restore --source=<oid> -- .          # весь каталог
```

- [ ] Пункт контекстного меню на коммите и на файле в списке
- [ ] Результат попадает в рабочее дерево как обычные незакоммиченные правки
- [ ] Перед выполнением — автоматический stash, если есть несохранённые изменения
- [ ] Запись в журнале Undo

**DoD:** после Rollback-To `HEAD` не изменился, ветка та же, изменения видны как обычный diff.

Ценность в том, что это **не** `git checkout <sha>`: пользователь не оказывается
в detached HEAD и не теряет ориентацию. Частая задача «посмотреть, как этот файл выглядел
три коммита назад, и вернуть» решается одним кликом.

## T12.2 · Split-Off Files — опасная

Выделить часть файлов уже совершённого коммита и вынести их в отдельный коммит до или
после исходного.

- [ ] В окне коммита мультивыбор файлов, действие `Split-Off…`
- [ ] Диалог: сообщение нового коммита и позиция (**до** или **после** исходного)
- [ ] Реализация через неинтерактивный rebase с `edit` на целевом коммите:
      `reset HEAD^ -- <files>` → коммит выбранного → коммит остатка → `rebase --continue`
- [ ] Прогресс и конфликты ведут себя как обычный rebase ([M11](M11-commit-debugger.md))
- [ ] `ORIG_HEAD` и журнал Undo до начала

**DoD:** разделение коммита из 10 файлов на 3 + 7 даёт два коммита, суммарное дерево
которых побитово совпадает с исходным.

Последнее — главная проверка: операция не имеет права потерять или изменить ни байта.

### Предупреждение, которое обязано быть в UI

Split-Off **переписывает историю начиная с выбранного коммита**: у всех последующих
коммитов меняются OID. Если коммит уже отправлен в удалённый репозиторий, синхронизация
потребует force-push, а у коллег история разъедется.

- [ ] Перед выполнением проверять, достижим ли коммит из upstream
- [ ] Если да — предупреждение отдельным текстом, а не мелким шрифтом в углу
- [ ] Для коммита, отправленного в защищённую ветку, действие недоступно

## Приёмка модуля

- [ ] Rollback-To не двигает `HEAD` и не создаёт коммитов
- [ ] Split-Off сохраняет содержимое дерева бит в бит
- [ ] Обе операции откатываются через Undo
- [ ] Предупреждение о переписывании истории показывается ровно тогда, когда оно уместно

## Риски

| Риск | Мера |
|---|---|
| Split-Off теряет часть изменений при конфликте | Тест на побитовое совпадение итогового дерева; остановка с понятным баннером вместо «тихого» продолжения |
| Пользователь не понимает, что переписал опубликованную историю | Явная проверка достижимости из upstream и отдельное предупреждение |
| Rollback-To затирает несохранённую работу | Автоматический stash перед выполнением |
