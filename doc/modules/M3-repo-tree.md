### T3.8 · Worktree как сущность первого класса

Расширение T3.5: worktree перестаёт быть «ещё одной командой» и становится объектом,
между которыми приложение переключается.

- [ ] Worktree показываются в дереве рядом с репозиторием, а не в отдельном диалоге
- [ ] У каждого — статус `clean` или `dirty`, обновляемый по `fs_watcher`
- [ ] Клик по ветке, уже занятой другим worktree, **переключает контекст приложения**
      на этот worktree вместо падения `fatal: already checked out`
- [ ] Перед переключением — предупреждение, если в текущем worktree есть незакоммиченное
- [ ] Заблокированные (`locked`) и отсутствующие worktree помечены отдельно

**DoD:** попытка checkout ветки, занятой другим worktree, приводит к переключению,
а не к ошибке.

**Почему это важно.** `already checked out in worktree` — одна из самых раздражающих
ошибок Git: она сообщает о проблеме, хотя пользователь хотел ровно того, что Git
и так может сделать.

## Известные ловушки

| Ловушка | Последствие | Как избежать |
|---|---|---|
| Рекурсия по сабмодулям без ограничения глубины | Зависание на циклических ссылках | Ограничение глубины и учёт посещённых путей |
| Открытие сабмодуля как отдельного репо без учёта `.git`-файла | Не находится репозиторий | `gix::discover` умеет читать `.git` как файл |
| Блокирующий `Fetch All` последовательно | Пять репозиториев по 10 секунд = минута | Параллельно, с ограничением одновременных задач |
| Хранение абсолютных путей без нормализации | Дубликаты при разном регистре на Windows | Канонизация пути перед сравнением |
