# M15 · Разделение бэкенда: работа с репозиторием там, где он лежит

**Статус:** `TODO` — спроектировано 21 сентября 2026, к реализации не приступали
**Веха:** F · **Зависит от:** M1, M3, M4

## Зачем

Репозиторий в WSL, открытый нативным клиентом через `\\wsl.localhost\…`, читается по
**9P** — сетевой файловой системе, которую обслуживает демон внутри виртуальной машины.
Каждый `lstat` — round trip через virtio-сокет: ~0.1–1 мс вместо ~2–5 мкс на NTFS.
`git status` на среднем репозитории делает десятки тысяч `lstat`, и 50 мс превращаются в
полминуты. Вдобавок `ReadDirectoryChangesW` по 9P не работает, поэтому watcher скатывается
в опрос — то есть в те же десятки тысяч `lstat`, только по таймеру.

Обойти это клиентом нельзя, пока клиент ходит по 9P. Значит, надо не ходить: перенести
чтение туда, где файлы лежат, и гонять через границу готовые ответы.

Запускать вместо этого весь Cogit внутри WSLg — не решение: файловая система станет
родной, но отрисовка пойдёт по RDP-каналу наружу из виртуалки. Это ровно та установка,
от которой пользователь уходит.

## Решение в одном абзаце

Слой команд перестаёт звать `AppState` напрямую и спрашивает у контекста, где живёт
репозиторий. Локальный — прямой вызов, как сегодня, без единой лишней миллисекунды.
Репозиторий в дистрибутиве — вызов уходит по stdio процессу `cogit-agent`, который живёт
на ext4 рядом с файлами. Окно остаётся нативным Windows.

## Границы

**Разрез проходит по признаку `repo: RepoId`.** Из 103 команд 79 берут его и маршрутизируются;
оставшиеся 24 — меню, раскладка, горячие клавиши, токены хостингов, аватары, контекстные
меню, окна, сканирование папок — к репозиторию отношения не имеют и всегда исполняются на
Windows. Правило механическое и проверяется грепом.

| Что | Где исполняется | Почему |
|---|---|---|
| Чтение объектов, `git`-процессы, хуки | дистрибутив | ради этого всё и затевается: `cargo test` в pre-commit должен идти на Linux |
| Watcher | дистрибутив | inotify на ext4 работает, `ReadDirectoryChangesW` по 9P — нет |
| Токены хостингов, запросы к API GitHub/GitLab | Windows | в дистрибутиве нет keyring, и незачем гонять секреты через пайп |
| Аутентификация самого git при push/pull | дистрибутив | тот же credential helper, что у пользователя в терминале |
| Аватары, меню, настройки, раскладка | Windows | к репозиторию отношения не имеют |

## Состав

| Единица | Что это | Зависит от |
|---|---|---|
| `crates/agent_api` | список команд и генерируемый из него протокол | `serde`, `specta`; **не** `tauri`, **не** ОС |
| `crates/cogit_agent` (bin) | `app_state` + диспетчер + цикл чтения stdin | `agent_api`, `app_state` |
| `src-tauri/src/remote.rs` | процесс агента, кадры, таблица идентификаторов | `agent_api` |

## Задачи

### T15.1 · Макрос протокола

Три варианта разреза рассмотрены: трейт на 79 типизированных методов (79 сигнатур в трёх
местах, гарантированно разъедется), один нетипизированный `call(method, params)` (лишает
локальный путь типов) и макрос. Взят макрос.

```rust
remote_api! {
    fn commit_files(repo: RepoId, rev: String) -> Vec<FileEntry>;
    fn diff_file(repo: RepoId, spec: DiffSpec, path: String, options: DiffOptions) -> FileDiff;
    …
}
```

- [ ] Из одного объявления генерируются: `Request`, `Response`, `dispatch()` для агента и
      типизированные методы клиента
- [ ] Новая команда — одна строка в списке, а не три правки в трёх файлах
- [ ] Тест: круговой прогон каждой команды через сериализацию и обратно

**DoD:** добавление команды в список и её отсутствие в диспетчере — ошибка компиляции.

### T15.2 · Транспорт

- [ ] Длиной-префиксованный JSON по stdin/stdout
- [ ] Три вида кадров от агента: `response { id, result | error }`,
      `chunk { stream, data }` / `end { stream }`, `event { kind, payload }`
- [ ] Ответы приходят не по порядку: сопоставление по `id`, не по очерёдности

**Почему stdio, а не TCP:** не нужен порт, файрвол и аутентификация, а время жизни агента
привязано к процессу — приложение упало, агент умер вместе с ним.

**DoD:** тест на паре in-memory каналов, без WSL: десять параллельных вызовов получают
свои ответы.

### T15.3 · Стриминг и события

- [ ] `load_commits` отдаёт чанки кадрами `chunk`, клиент пересылает их в `tauri::ipc::Channel`
- [ ] Watcher в дистрибутиве шлёт `event` без запроса; клиент кладёт их в ту же шину `AppEvent`
- [ ] Отмена: закрытие потока со стороны клиента останавливает обход в агенте

**DoD:** граф на 50 000 коммитов из дистрибутива укладывается в тот же бюджет первого
экрана, что и локальный ([00-roadmap.md](../00-roadmap.md), обещание 1).

### T15.4 · Идентификаторы и пути

- [ ] `RepoId` выдаёт Windows-сторона; `remote.rs` держит таблицу
      `RepoId (Windows) → RepoId (агента)`
- [ ] Корень переводится ровно в одном месте — при открытии:
      `\\wsl.localhost\Ubuntu\home\brano\x` ↔ `/home/brano/x`
- [ ] Всё остальное уже относительное с `/` ([01-architecture.md](../01-architecture.md)),
      переводить нечего

**DoD:** открыть локальный и удалённый репозиторий одновременно, обе панели работают.

### T15.5 · Жизненный цикл и версии

- [ ] Один агент на дистрибутив, старт ленивый — при первом удалённом открытии
- [ ] Смерть, когда закрыт последний репозиторий этого дистрибутива, и при выходе
- [ ] Рукопожатие с версией; не совпала или файла нет — клиент кладёт вшитый бинарник
      в `~/.cogit/bin/cogit-agent` и стартует заново

**Обновление приложения обновляет агента само.** Пользователь об этом не знает.

**DoD:** подменить агента на старую версию — он молча заменяется рабочим.

### T15.6 · Когда что-то не так

- [ ] WSL не установлен, дистрибутив не поднят, агент не стартует, протокол сломался —
      репозиторий открывается в состоянии «недоступен» с причиной в панели
- [ ] Ни одного тихого зависания: это ровно та болезнь, от которой лечимся
- [ ] Смерть агента на середине операции — ошибка вызывающему, а не вечное ожидание

**DoD:** убить процесс агента снаружи во время работы — приложение сообщает и остаётся живым.

### T15.7 · Сборка и упаковка

- [ ] Цель `x86_64-unknown-linux-musl`, сборка `wsl.exe -- cargo build --release -p cogit-agent`
- [ ] Результат в `src-tauri/resources/`, вшивается в оба установщика
- [ ] `doc/13-distribution.md` дополняется разделом про агента

**Почему musl, а не glibc:** бинарник, собранный на Ubuntu 24.04, не запустится на
дистрибутиве с более старым glibc. Статическая сборка запускается везде. Цена —
чуть более медленный аллокатор; для процесса, который упирается в диск, это не видно.

**Почему сборка внутри WSL, а не кросс-линкер:** WSL на машине разработчика уже есть,
а возня с кросс-тулчейном под Windows не окупается. CI потом сделает это на ubuntu-runner.

## Что выпускаем

```
Cogit_0.2.0_x64-setup.exe   ← основной, NSIS
Cogit_0.2.0_x64_en-US.msi   ← для корпоративной раскатки
cogit.exe                   ← portable
      внутри обоих установщиков: resources/cogit-agent (~8 МБ, статический ELF)
```

Linux-гуя не делаем: цель — работа с репозиториями в WSL из нативного окна Windows, а не
вторая платформа со своими багами отрисовки и своим CI. Portable-вариант получает агента
файлом рядом; установщик остаётся основным способом, потому что он же закрывает
WebView2 Runtime ([13-distribution.md](../13-distribution.md)).

## Известные ловушки

| Ловушка | Симптом | Мера |
|---|---|---|
| Локальный путь платит сериализацию | ровное замедление на всём | локальный репозиторий зовёт `AppState` напрямую; пайпа в этом пути нет вовсе |
| Два пространства `RepoId` | чужой репозиторий под своим номером | нумерует только Windows-сторона, агент получает её номера через таблицу |
| glibc агента новее, чем в дистрибутиве | агент не стартует, репозиторий «недоступен» | musl |
| Агент пережил приложение | процесс-сирота в дистрибутиве | stdio: закрытие пайпа — сигнал к выходу |
| Сборка агента забыта перед релизом | установщик без агента, WSL молча не работает | проверка наличия `resources/cogit-agent` в `tauri.conf.json` и в чек-листе релиза |

## Приёмка модуля

- [ ] Локальный репозиторий не медленнее, чем до разделения — замер теми же тестами
      `performance.rs`
- [ ] Репозиторий в WSL открывается и отрисовывается в тех же бюджетах, что локальный
- [ ] Хуки в WSL-репозитории исполняются на Linux
- [ ] Правка файла в терминале дистрибутива видна в панелях без нажатия Refresh
- [ ] Выключенный WSL не мешает обычной работе

## Сначала измерить

**Реализации предшествует замер.** Оснастка уже есть: `blocking()` профилирует все точки,
`report_timing` пишет в лог. Открыть один и тот же репозиторий с `C:` и с
`\\wsl.localhost\`, сравнить `open_repository`, `repo_status`, `load_commits`,
`worktree_files`.

Это не формальность. Cogit — не JVM: `gix` читает пакфайлы напрямую и не спавнит процессы
на чтении, поэтому там, где SmartGit фризил, Cogit может оказаться просто «заметно
медленнее». Тогда хватит дешёвой меры — распознавать `\\wsl.localhost` и выключать всё,
что множит `lstat`, — и агента городить незачем. Если множитель окажется в десятки раз,
цифры сами скажут, что пора, и заодно покажут, какие команды греют больше всего.
