# M11 · Commit Debugger — граф во время незавершённой операции

**Статус:** `WIP` — T11.1 готова, T11.2 частично · **Веха:** E · **Зависит от:** M4, M5, M6

## Зачем

Когда `rebase` останавливается на конфликте, обычный клиент показывает сломанный граф,
`HEAD` в непонятном месте и предложение «разрулите в консоли». Пользователь теряет
ориентацию ровно в тот момент, когда она нужнее всего.

Идея модуля: во время переходной операции граф не ломается, а **показывает саму операцию** —
что уже применено, что применяется сейчас, что осталось. Отсюда название: отладчик, в котором
видно текущую позицию и стек оставшихся шагов.

Это главный отличительный элемент Cogit. Ни SmartGit, ни GitKraken, ни Fork так не делают.

## Задачи

### T11.1 · Баннер переходного состояния

Появляется над списком коммитов, фон предупреждающий (янтарный, `--status-modify`
с заливкой 12%).

| Состояние | Заголовок | Кнопки |
|---|---|---|
| Rebase | `The working tree is in rebasing-state.` | `Continue…` `Skip…` `Abort…` |
| Merge | `The working tree is in merging-state.` | `Continue…` `Abort…` |
| Cherry-pick | `The working tree is in cherry-picking-state.` | `Continue…` `Skip…` `Abort…` |
| Revert | `The working tree is in reverting-state.` | `Continue…` `Abort…` |
| Bisect | `The working tree is in bisecting-state.` | `Good` `Bad` `Reset` |

- [x] Состояние определяется по маркерам из [03-git-semantics.md §4](../03-git-semantics.md#4-состояния-репозитория)
- [x] Обновляется по событиям `fs_watcher`, а не по таймеру
- [x] Неприменимые кнопки скрыты, а не отключены — набор действий зависит от операции
- [x] Ошибка любой из кнопок открывает диалог с сырым выводом ([INV-05](../01-architecture.md#inv-05))

**DoD:** каждое состояние воспроизводится фикстурой из M9 и показывает свой баннер.

### T11.2 · Виртуальные узлы графа

Во время rebase первые строки списка описывают не историю, а **текущий шаг операции**:

```
● Working Tree (3 changes)
● Index (1 change), rebasing: Fix parser type
│
◌ [todo +2] Optimize algorithm          ← ещё не применён
◌ [todo +1] Change recursive function
│
● master ▶ Add bencode reader           ← точка применения
● Initial commit
```

- [x] Узел `Working Tree (<N> changes)` — всегда первый, счётчик из `status`
- [x] Узел `Index (<N> changes), rebasing: <сообщение>` — имя коммита из `.git/rebase-merge/message`
- [x] Оставшиеся коммиты читаются из `.git/rebase-merge/git-rebase-todo` и рисуются
      приглушённо, с бейджем действия
- [x] Указатель `▶` на точке применения (`.git/rebase-merge/onto`)
- [ ] Узлы пока рисуются блоком **над** виртуализированным списком, а не строками внутри него

**DoD:** rebase с конфликтом на середине показывает корректный прогресс; после `Continue`
список перестраивается без перезагрузки всего графа.

**Замечание по реализации.** Формат `.git/rebase-merge/` — внутренний, Git его не
документирует как стабильный. Парсер должен деградировать мягко: не смог разобрать
`git-rebase-todo` — показываем баннер без списка оставшихся шагов, но не падаем.

### T11.3 · Пошаговый rebase

Интерактивный rebase с остановкой после **каждого** коммита, чтобы между шагами можно было
прогнать `cargo check` или тесты.

- [ ] Флажок «Pause after each commit» в диалоге rebase
- [ ] Реализация через вставку `break` после каждой строки `git-rebase-todo` (Git ≥ 2.20)
- [ ] Поле «Команда проверки» — запускается автоматически на каждой паузе, вывод в Output
- [ ] Провал проверки подсвечивает шаг красным, но не прерывает rebase: решает пользователь
- [ ] `ORIG_HEAD` и журнал Undo фиксируются до старта ([INV-12](../01-architecture.md#inv-12))

**DoD:** rebase пяти коммитов с командой `cargo check` останавливается пять раз и
показывает результат проверки на каждом шаге.

**Почему это ценно:** «сборка сломалась где-то в этих пяти коммитах» — обычная ситуация
при подготовке PR, и обычно её разбирают вручную через `git rebase -i` с `break`.

## Приёмка модуля

- [ ] Все пять переходных состояний показывают баннер с верными кнопками
- [ ] Граф во время rebase читается без обращения к консоли
- [ ] Повреждённый или незнакомый `git-rebase-todo` не роняет UI
- [ ] `Abort` возвращает репозиторий ровно в исходное состояние (проверено сравнением OID всех ссылок)

## Риски

| Риск | Мера |
|---|---|
| Формат `.git/rebase-merge/` недокументирован и может меняться | Парсер терпимый; при неудаче баннер работает, список шагов скрывается |
| Rebase применяет чужие коммиты — цена ошибки высока | Undo-журнал обязателен до первого шага |
| Виртуальные узлы смешиваются с настоящими в модели данных | Отдельный тип строки; у виртуального узла нет OID, и это гарантируется типом |
