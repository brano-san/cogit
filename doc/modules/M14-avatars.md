# M14 · Аватары авторов

Статус: `TODO`. Зависит от: M1, M4. Документ плана — реализации пока нет.

Аватар рядом с коммитом — то, за что цепляется глаз при просмотре чужой истории. В SmartGit
это Gravatar; мы делаем то же, а GitHub и GitLab добавляем только там, где это не тянет за
собой авторизацию.

## 1. Что именно строим

Квадратная картинка 16×16 (HiDPI — 32×32) слева от имени автора в графе, в панели коммита и
в blame. Никаких аватаров в списках файлов и ссылок: там строка и так плотная.

## 2. Источники и приоритет

| Источник | Как получаем | Нужна ли авторизация |
|---|---|---|
| Gravatar | `https://www.gravatar.com/avatar/<md5(lowercase(trim(email)))>?s=64&d=404` | нет |
| GitHub | `https://avatars.githubusercontent.com/u/<id>` через `https://api.github.com/search/users?q=<email>+in:email` | для поиска — да, 10 запросов в час без токена |
| GitLab | `https://gitlab.com/api/v4/avatar?email=<email>&size=64` | нет |

**Gravatar — всегда по умолчанию.** Он не требует ни токена, ни знания хостинга, и один
запрос отвечает по почте напрямую.

GitLab даёт ровно тот же контракт (почта на входе, URL картинки на выходе) без авторизации —
его добавляем вторым. GitHub требует поиска пользователя по почте, а это авторизованный
запрос с лимитом 10/час; поэтому GitHub включается только когда в keyring уже лежит токен
для `github.com`, и молча выключается, когда его нет.

Настройка `avatarSource`: `gravatar` (по умолчанию) · `gravatarThenGitlab` · `gravatarThenGithub` · `off`.
Запасной вариант всегда один и тот же и никогда не ходит в сеть — см. T14.4.

## 3. Задачи

### T14.1 · Кэш на диске

- [ ] Каталог `<app_cache_dir>/avatars/<md5>.png`, плоский, без подпапок
- [ ] Индекс `index.json`: `md5 → { fetched_at, source, missing }`
- [ ] Отрицательный результат кэшируется тоже (`missing: true`), иначе каждая отрисовка
      графа бьёт в сеть за одним и тем же отсутствующим адресом
- [ ] TTL: 30 дней для найденного, 7 дней для отсутствующего
- [ ] Предел каталога 64 МБ, вытеснение по дате обращения

**DoD:** второй запуск с тем же репозиторием не делает ни одного сетевого запроса.

### T14.2 · Загрузка вне отрисовки

- [ ] Одна очередь на приложение, не больше 4 запросов одновременно
- [ ] Таймаут 5 с на запрос, один повтор, дальше — `missing`
- [ ] Строка графа **никогда** не ждёт аватар: рисуется запасной вариант, картинка
      подменяется событием `avatar-ready { email, path }`
- [ ] Видимое окно графа имеет приоритет: прокрутка отменяет очередь на ушедшие строки

**DoD:** открытие репозитория на 50 000 коммитов при выключенной сети укладывается в тот же
бюджет 300 мс, что и сейчас ([00-roadmap.md](../00-roadmap.md), обещание 1).

### T14.3 · Приватность

- [ ] Источник `off` не делает ни одного запроса и не создаёт каталог кэша
- [ ] Почта уходит на Gravatar **только** как MD5; в GitLab — открытым текстом, поэтому
      этот источник помечен в настройках как «отправляет адрес почты на gitlab.com»
- [ ] Ни одного запроса до того, как пользователь выбрал источник: при первом запуске
      показывается запрос в строке настроек, а не молчаливое включение
- [ ] Ни один URL с почтой не попадает в лог; `redact_command` расширяется на HTTP

**DoD:** запуск с `avatarSource: off` и снятым сетевым интерфейсом не пишет в лог ни одной
строки об аватарах.

### T14.4 · Запасной вариант

- [ ] Инициалы автора на фоне, цвет — детерминированная функция от почты
- [ ] Тот же вид, пока картинка грузится, — чтобы строка не прыгала
- [ ] Ничего не грузится из сети: это локальный рендер в канвасе

**DoD:** при выключенной сети граф выглядит законченным, а не дырявым.

### T14.5 · Отображение

- [ ] Колонка аватара в `CommitList`, ширина фиксированная, учтена в `graph-geometry`
- [ ] Включение и выключение — `View → Author Avatars`, чекбокс как у Commit Overlap
- [ ] HiDPI: запрашиваем `s=64`, рисуем в 16 CSS-пикселей

## 4. Известные ловушки

| Ловушка | Симптом | Мера |
|---|---|---|
| Gravatar без `d=404` отдаёт заглушку | «Найден» аватар у каждого автора | `d=404`, 404 означает `missing` |
| Почта вида `12345+user@users.noreply.github.com` | Gravatar не находит | Распознаём шаблон noreply и идём сразу в GitHub, если он включён |
| Регистр и пробелы в почте | Один автор — два разных MD5 | `trim` и `to_lowercase` **до** хэширования |
| Загрузка внутри отрисовки канваса | Падение FPS на прокрутке | Канвас читает только готовый `HTMLImageElement` из кэша в памяти |
| Кэш растёт без предела | Каталог на гигабайты | Предел 64 МБ и вытеснение (T14.1) |
