# M9 · Тестовые фикстуры

**Статус:** `DONE` (19 сентября 2026) · **Веха:** A · **Зависит от:** M0 · **Блокирует:** M1, M4, M6, M7

Реализуется **вторым**, сразу после костяка. Без генератора репозиториев нечем тестировать
всё остальное, а тестирование на живых репозиториях разработчика невоспроизводимо.

Общая стратегия — [09-testing.md](../09-testing.md).

## Задачи

### T9.1 · Базовый билдер
- [x] Тип `Fixture`, владеющий `TempDir`, плюс свободные функции на каждую форму
      (fluent-билдер из первой редакции плана не понадобился: формы фиксированы,
      а цепочка вызовов только добавила бы способов собрать бессмысленный репозиторий)
- [x] Изоляция окружения: `HOME`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` во временную папку
- [x] Детерминированные `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE`, фиксированный автор
- [x] Явная установка `core.autocrlf=false` по умолчанию, с возможностью переопределить
- [x] Удаление временной папки при drop, включая случай паники теста

**DoD:** два подряд вызова `linear(5)` дают **идентичные** OID коммитов.

Детерминированность OID — не роскошь: без неё snapshot-тесты графа невозможны.

### T9.2 · Формы репозиториев

Полный список — [09-testing.md §4](../09-testing.md#4-test_fixtures--генератор-репозиториев).

- [x] `linear(n)`, `branched()`, `diamond()`, `octopus()`, `two_roots()`
- [x] `conflicted()`, `detached_head()`, `empty()`, `bare()`
- [x] `with_submodule()`, `with_worktree()`, `with_stashes(n)`
- [x] `crlf_files()`, `renames()`, `filemode_change()`, `unicode_paths()`
- [x] `stress(n)` — по умолчанию 10 000 коммитов

**DoD:** у каждой формы есть тест, проверяющий её структуру через системный `git`
(например, `diamond()` проверяется тем, что `git rev-list --merges` даёт ровно один коммит).

**Платформенные ловушки, найденные при разборе плана:**

| Форма | Ловушка | Решение |
|---|---|---|
| `with_submodule()` | Git ≥ 2.38 отказывается добавлять сабмодуль по `file://` — защита от CVE-2022-39253 | Передавать `-c protocol.file.allow=always` только на команду добавления |
| `filemode_change()` | На Windows Git не отслеживает бит исполнения (`core.filemode=false`), обычный `chmod` ничего не даст | Менять режим в индексе: `git update-index --chmod=+x` |
| `bare()` | Нет рабочей директории, поэтому `commit_file` неприменим | Собирать обычный репозиторий и клонировать его с `--bare` |
| `conflicted()` | `git merge` завершается ненулевым кодом — это **ожидаемый** результат, а не сбой | Не считать ненулевой код ошибкой для этой команды |
| `crlf_files()` | Глобальный `core.autocrlf=true` у разработчика исказит содержимое | Уже закрыто изоляцией окружения из T9.1 |

### T9.3 · Производительность
- [x] Массовые коммиты создаются через `git fast-import`, а не циклом `git commit`
- [x] Каждый вызов `stress(n)` независим — кэширования нет и не требуется
- [x] Бюджеты установлены по факту замера

**DoD:** полный прогон `cargo test -p test_fixtures` укладывается в 30 секунд — **~15 с**.

#### Замеры (Windows 11, Git 2.51, 19 сентября 2026)

| Фикстура | Время | Запусков `git` |
|---|---|---|
| `linear(5)` | **934 мс** | ~17 |
| `diamond()` | 833 мс | ~15 |
| `with_submodule()` | 1883 мс | ~20 плюс clone |
| `stress(1 000)` | 191 мс | 3 |
| `stress(10 000)` | **367 мс** | 3 |

Главный вывод, ради которого стоило мерить: **десять тысяч коммитов создаются в 2,5 раза
быстрее пяти**. Стоимость фикстуры определяется числом запусков процесса, а не объёмом
работы, которую Git выполняет. На Windows один запуск `git` обходится в 40–60 мс, и это
полностью перекрывает всё остальное.

Практические следствия:

- Добавлять команды `git` в фикстуру дорого; писать файлы напрямую — бесплатно.
  Поэтому `.git/config` пишется одним файлом, а не четырьмя вызовами `git config`.
- `linear(n)` имеет смысл перевести на `fast-import`, если время прогона станет мешать.
  Пока 15 секунд на весь крейт — терпимо, и переписывание отложено.

**Исправление плана №1.** Первая редакция говорила «`stress` создаётся один раз и
переиспользуется», что противоречит антипаттерну «общая фикстура, изменяемая тестами»
из [09-testing.md §10](../09-testing.md#10-антипаттерны). Замер показал, что вопрос вообще
не стоит: `stress(10 000)` занимает 367 мс, так что кэшировать нечего. Схема с эталоном
и `git clone --local` тоже не понадобилась.

**Исправление плана №2.** Бюджет «`linear(5)` быстрее 100 мс» был назначен без замера
и оказался занижен **в девять раз**. Хороший урок: назначенный «из головы» бюджет либо
недостижим, либо бессмысленно мягок, и в обоих случаях ничего не проверяет.

## Проверка изоляции окружения

Защита от самого коварного класса ошибок — «у меня зелёное, у тебя красное».

Первая редакция плана предлагала выставить в процессе теста `GIT_CONFIG_GLOBAL` на файл
с `core.autocrlf=true`. Так сделать нельзя: в edition 2024 `std::env::set_var` помечена
`unsafe`, а в проекте `unsafe_code = "deny"`; вдобавок правка окружения процесса гонится
с параллельными тестами.

Реализовано иначе, и получилось строже — проверяется не симптом, а причина:

| Тест | Что доказывает |
|---|---|
| `the_developer_global_config_is_invisible_to_fixtures` | `git config --global --list` внутри фикстуры пуст: глобальная область не видна вовсе |
| `fixtures_pin_autocrlf_off` | Действующее значение `core.autocrlf` — `false`, каким бы оно ни было у разработчика |
| `crlf_file_keeps_carriage_returns_in_the_blob` | CRLF доживает до объектной базы без искажения |

## Что НЕ делается в M9

Фикстуры не знают про `gix` и не используют его: они должны создавать репозитории тем же
инструментом, которым их создаёт пользователь, — системным `git`. Иначе тесты проверяли бы
согласованность `gix` с самим собой.
