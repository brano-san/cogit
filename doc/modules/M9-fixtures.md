# M9 · Тестовые фикстуры

**Статус:** `TODO` · **Веха:** A · **Зависит от:** M0 · **Блокирует:** M1, M4, M6, M7

Реализуется **вторым**, сразу после костяка. Без генератора репозиториев нечем тестировать
всё остальное, а тестирование на живых репозиториях разработчика невоспроизводимо.

Общая стратегия — [09-testing.md](../09-testing.md).

## Задачи

### T9.1 · Базовый билдер
- [ ] `FixtureBuilder` с fluent-API, владеющий `TempDir`
- [ ] Изоляция окружения: `HOME`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` во временную папку
- [ ] Детерминированные `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE`, фиксированный автор
- [ ] Явная установка `core.autocrlf=false` по умолчанию, с возможностью переопределить
- [ ] Удаление временной папки при drop, включая случай паники теста

**DoD:** два подряд вызова `linear(5)` дают **идентичные** OID коммитов.

Детерминированность OID — не роскошь: без неё snapshot-тесты графа невозможны.

### T9.2 · Формы репозиториев

Полный список — [09-testing.md §4](../09-testing.md#4-test_fixtures--генератор-репозиториев).

- [ ] `linear(n)`, `branched()`, `diamond()`, `octopus()`, `two_roots()`
- [ ] `conflicted()`, `detached_head()`, `empty()`, `bare()`
- [ ] `with_submodule()`, `with_worktree()`, `with_stashes(n)`
- [ ] `crlf_files()`, `renames()`, `filemode_change()`, `unicode_paths()`
- [ ] `stress(n)` — по умолчанию 10 000 коммитов

**DoD:** у каждой формы есть тест, проверяющий её структуру через системный `git`
(например, `diamond()` проверяется тем, что `git rev-list --merges` даёт ровно один коммит).

### T9.3 · Производительность
- [ ] `linear(5)` создаётся быстрее 100 мс
- [ ] `stress(10_000)` создаётся один раз на процесс и переиспользуется (ленивая статика)
- [ ] Массовые коммиты создаются через `git fast-import`, а не циклом `git commit`

**DoD:** полный прогон `cargo test -p test_fixtures` укладывается в 30 секунд.

Цикл из 10 000 вызовов `git commit` на Windows занял бы минуты — `fast-import` решает это
на порядок быстрее.

### T9.4 · Удобство использования
- [ ] Хелперы: `fixture.path()`, `fixture.oid("HEAD~2")`, `fixture.run_git(&[...])`
- [ ] Возможность дописать историю после создания: `fixture.commit_file("a.txt", "text")`
- [ ] Понятная диагностика: при падении `git` показывается его `stderr`

**DoD:** написание нового теста на существующей фикстуре занимает менее 10 строк.

## Приёмка модуля

```bash
cargo test -p test_fixtures
```

- [ ] Все формы репозиториев создаются и проверены
- [ ] OID детерминированы между запусками и между машинами
- [ ] Глобальный `.gitconfig` разработчика не влияет на результат
- [ ] Временные папки удаляются даже при панике теста
- [ ] `stress(10_000)` не замедляет обычный прогон

## Проверка изоляции окружения

Отдельный тест: выставить в окружении `GIT_CONFIG_GLOBAL` на файл с `core.autocrlf=true`
и убедиться, что фикстура с LF-файлами всё равно создаёт LF.

Этот тест защищает от самого коварного класса ошибок — «у меня зелёное, у тебя красное».

## Что НЕ делается в M9

Фикстуры не знают про `gix` и не используют его: они должны создавать репозитории тем же
инструментом, которым их создаёт пользователь, — системным `git`. Иначе тесты проверяли бы
согласованность `gix` с самим собой.
