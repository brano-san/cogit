### T4.9 · Drag-and-drop в графе

Прямое манипулирование историей мышью. Каждое действие деструктивно, поэтому каждое
проходит через журнал Undo ([INV-12](../01-architecture.md#inv-12)).

- [ ] **Ветка на ветку.** Бросок открывает нативное меню: `Merge`, `Rebase onto`,
      `Fast-forward` (последний пункт активен только если перемотка возможна)
- [ ] **Коммит внутри ветки.** Перетаскивание меняет порядок (`reorder`) или,
      при броске на другой коммит, объединяет (`squash`)
- [ ] Обе операции выполняются фоновым `git rebase -i` через `GIT_SEQUENCE_EDITOR`
- [ ] Предпросмотр до подтверждения: что получится и какие коммиты сменят OID
- [ ] Конфликт переводит UI в состояние из [M11](M11-commit-debugger.md)

**DoD:** перестановка двух коммитов и squash двух соседних проходят целиком в UI;
`Abort` возвращает исходное состояние.

**Замечание.** Цель перетаскивания определяется по строке и дорожке, вычисляемым из
координат курсора математически — тем же способом, что и попадание по узлу (T4.4).
Отдельная DOM-разметка для drop-зон поверх виртуализированного списка развалится
при скролле.

## Известные ловушки

| Ловушка | Последствие | Как избежать |
|---|---|---|
| Canvas высотой во всю историю | Превышение лимита размера холста в браузере | `sticky`-холст размером с видимую область |
| Отрисовка прямо в обработчике `scroll` | Рассинхрон холста и DOM | Только `requestAnimationFrame` |
| Игнорирование `devicePixelRatio` | Мыльные линии на HiDPI | Масштабирование холста и `setTransform` |
| Пересчёт цветов при дозагрузке чанка | Ветки меняют цвет на глазах | Сохранять счётчик цветов в курсоре |
| Переменная высота строки | Невозможно синхронизировать с холстом | Фиксированная высота |
| Раскладка графа в JS | Требует весь граф в Webview | Считать на бэкенде ([INV-02](../01-architecture.md#inv-02)) |
| Rebase без фиксации `ORIG_HEAD` | Потеря коммитов при ошибке | Журнал Undo до запуска |
