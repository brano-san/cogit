# Cogit — Архитектура

> Читать после [00-roadmap.md](00-roadmap.md). Здесь — границы компонентов, потоки данных,
> модель потоков исполнения и реестр инвариантов, нарушать которые нельзя без правки этого файла.

## 1. Слои

```text
┌──────────────────────────────────────────────────────────────────────┐
│  frontend/  — Svelte 5 (Runes) + TypeScript + CodeMirror 6 + Lezer   │
│  Отвечает за: рендеринг, виртуализацию, подсветку синтаксиса,        │
│               локальное состояние UI, Canvas-отрисовку графа.        │
│  Не отвечает за: любую логику Git.                                   │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  typed IPC (tauri-specta)
                                │  · invoke  — запрос/ответ
                                │  · Channel — стриминг чанков
                                │  · Event   — push от бэкенда
┌───────────────────────────────┴──────────────────────────────────────┐
│  src-tauri/  — тонкий слой обвязки                                   │
│  Отвечает за: регистрацию команд, окна, меню, плагины, DI состояния. │
│  Не отвечает за: бизнес-логику. Тело команды ≈ 10 строк.             │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  обычные Rust-вызовы
┌───────────────────────────────┴──────────────────────────────────────┐
│  crates/  — вся бизнес-логика, не знает о Tauri                      │
│                                                                      │
│   app_state ──────► git_engine ──► (gix, git CLI)                    │
│       │       ├───► diff_engine ─► (imara-diff, similar, tree-sitter)│
│       │       ├───► graph_engine                                     │
│       │       └───► fs_watcher ──► (notify)                          │
│       └── шина событий, реестр открытых репозиториев, keyring        │
└──────────────────────────────────────────────────────────────────────┘
```

**Правило зависимостей:** стрелки идут только вниз. `git_engine` не знает про `app_state`.
Ни один крейт в `crates/` не зависит от `tauri` — исключение только `specta` ради derive-макросов,
это чистая типовая библиотека без рантайма Tauri.

Почему так: движки должны тестироваться через `cargo test -p <crate>` за секунды,
без запуска Webview и без GUI-окружения.

## 2. Контракты крейтов

Для каждого крейта: **что делает** · **как используется** · **от чего зависит**.

### `git_engine`
- **Что:** читает объекты Git через `gix` и выполняет мутации через системный `git` CLI.
  Единственное место в проекте, которое знает, как устроен Git.
- **Как:** `RepoManager::open(path)` возвращает `RepoHandle`; далее методы чтения
  (`status`, `branches`, `submodules`, `refs`, `commit_range`) и мутации (`stage`, `commit`, `push`, …).
- **Зависит от:** `gix`, `tokio` (process), `thiserror`, `tracing`, `serde`, `specta`.
- **Ключевой тип:** `GitCommandError` — см. [INV-05](#inv-05) и [03-git-semantics.md](03-git-semantics.md).

### `diff_engine`
- **Что:** превращает пару текстов (или blob-ов) в структуру `FileDiff` — блоки, ханки,
  внутристрочные изменения. Плюс синтаксическое 3-way слияние через `tree-sitter`.
- **Как:** `diff_texts(old, new, opts)` возвращает `FileDiff`. Чистая функция,
  без I/O и без состояния — идеальна для `rayon` и property-тестов.
- **Зависит от:** `imara-diff`, `similar`, `tree-sitter`, `rayon`.
- **Подробности:** [08-diff-engine.md](08-diff-engine.md).

### `graph_engine`
- **Что:** топологическая сортировка DAG коммитов и раскладка по дорожкам (lanes).
- **Как:** `layout(commits, cursor)` возвращает `GraphRow` на каждый коммит — колонку
  узла и сегменты строки для Canvas.
- **Зависит от:** только `serde`/`specta`/`rayon`. **Не зависит от `gix`** — на вход приходят
  простые пары «oid + родители», что делает крейт тестируемым на голых id без единого репозитория.
- **Подробности:** [07-graph-rendering.md](07-graph-rendering.md).

### `fs_watcher`
- **Что:** следит за изменениями в `.git` и рабочей директории, отдаёт дебаунснутые события.
- **Как:** `Watcher::spawn(repo_path, tx)` возвращает `WatcherHandle`; шлёт `RepoChanged { kind }`.
- **Зависит от:** `notify`, `notify-debouncer-mini`, `ignore` (для фильтрации по `.gitignore`).
- **Ограничения:** [INV-06](#inv-06).

### `app_state`
- **Что:** реестр открытых репозиториев, группы/виртуальные папки, шина событий, доступ к keyring.
- **Как:** `AppState` хранится в Tauri через `.manage()`; команды получают его как `State<AppState>`.
- **Зависит от:** все остальные крейты, `parking_lot`, `tokio::sync::broadcast`, `keyring`.
- **Это единственный крейт с изменяемым глобальным состоянием.** Всё остальное — чистые функции
  и короткоживущие хэндлы.

### `test_fixtures`
- **Что:** программно создаёт временные Git-репозитории заданной формы.
- **Как:** билдер вида `FixtureBuilder::new().commits(5).branch("dev").merge().build()`,
  результат владеет `TempDir` и чистит его при drop.
- **Зависит от:** `tempfile`, системный `git`.
- **Используется только в `[dev-dependencies]`.**

## 3. Модель потоков исполнения

Три вида нагрузки — три механизма. Путаница между ними даёт либо фризы UI, либо голодание рантайма.

| Нагрузка | Механизм | Примеры |
|---|---|---|
| I/O, процессы, таймеры, сеть | `tokio` async | `git push`, `git fetch`, чтение конфигов |
| CPU, короткая (< 5 мс) | прямо в async-задаче | форматирование даты, парсинг имени ref |
| CPU, длинная / блокирующий I/O | `tokio::task::spawn_blocking` | обход дерева через `gix`, чтение больших blob-ов |
| CPU, длинная и распараллеливаемая | `rayon` внутри `spawn_blocking` | дифф 500 файлов, раскладка графа на 50k коммитов |

**Никогда** не вызывай `rayon::join` или `par_iter` прямо в async-задаче Tokio: rayon блокирует
воркер-поток Tokio, и весь рантайм — включая IPC — встаёт. Оборачивай в `spawn_blocking`.

Связь между мирами:

| Откуда → куда | Канал |
|---|---|
| async ↔ async | `tokio::sync::mpsc` |
| бэкенд → много подписчиков | `tokio::sync::broadcast` |
| rayon или OS-поток → async | `crossbeam-channel` + приём в `spawn_blocking` |
| синхронная защита данных | `parking_lot::{Mutex, RwLock}` — **никогда не удерживать гард через await** |

## 4. Потоки данных

### 4.1. Открытие репозитория
```text
UI: клик "Open"
  └─► invoke open_repository(path)
        └─► app_state: регистрирует RepoHandle, запускает fs_watcher
              └─► git_engine (spawn_blocking): читает HEAD, refs, status
                    └─► ответ: RepoSummary { head, branches[], counts }
        └─► параллельно: Event "repo-opened" → все окна обновляют дерево репозиториев
```

### 4.2. Загрузка истории (стриминг)
```text
UI: открытие репозитория, смена ссылок, фильтр
  └─► invoke load_commits(repo_id, query, channel)
        └─► git_engine: итератор коммитов через gix (spawn_blocking)
              └─► graph_engine: раскладка дорожек для чанка → кэш графа в AppState
                    └─► channel.send(GraphProgress { generation, total, isLast })  ← не чаще раза в 50 мс
UI: список сообщает видимые строки
  └─► invoke graph_window(repo_id, generation, start, 128)
        └─► UI: блок строк; Canvas и строки рисуют видимую область
```
Почему чанками — [INV-02](#inv-02).

### 4.3. Реакция на изменение файлов
```text
notify → debouncer (100 мс) → fs_watcher фильтрует путь
  └─► broadcast: RepoChanged { kind: Index | Head | WorkingTree | Refs }
        └─► src-tauri: emit Event в окна
              └─► UI: помечает панель как устаревшую, запрашивает только затронутые данные
```
UI **не перезагружает всё** — по полю `kind` обновляется только нужная панель.

### 4.4. Мутация с ошибкой
```text
UI: "Push"
  └─► invoke push(repo_id, remote, refspec)
        └─► git_engine: tokio::process::Command("git push ...")
              exit_code != 0
              └─► Err(GitCommandError { command, exit_code, stdout, stderr })
                    └─► UI: Git Error Dialog — сырой stderr в моноширинном блоке,
                            URL кликабельны, кнопка "Copy Output"
```

## 5. Реестр инвариантов

Нарушение любого пункта — это правка **этого файла** с обоснованием, а не «исключение в одном месте».

<a id="inv-01"></a>
### INV-01 · Подсветка синтаксиса живёт на фронтенде
Токены подсветки **не** передаются из Rust в Webview. Подсветкой занимается Lezer внутри CodeMirror 6.
`tree-sitter` в Rust используется только для AST-дифов и синтаксического слияния.
*Почему:* сериализация миллионов токенов через IPC на каждый скролл — главный источник тормозов.

<a id="inv-02"></a>
### INV-02 · История коммитов не передаётся целиком
Раскладку всей истории держит Rust (`AppState::build_graph`). Webview получает через
`tauri::ipc::Channel` только прогресс обхода — сколько строк готово — и запрашивает строки
окнами по видимой области (`graph_window`, блоки по 128). Прочие списки длиннее ~500
элементов идут через `Channel` чанками по 100–200. Возврат монолитного JSON запрещён.
*Почему:* сериализация и парсинг 50 000 объектов замораживают Webview на секунды, а окно
в 128 строк — десятки килобайт (R-193).

<a id="inv-03"></a>
### INV-03 · Линии графа рисуются на Canvas 2D
DOM-узлы используются только для строк коммитов (виртуализированный список).
Сплайны, точки и рёбра — `<canvas>` под списком.
*Почему:* тысячи SVG-путей в DOM убивают FPS при скролле.

<a id="inv-04"></a>
### INV-04 · Логирование неблокирующее, лог не более 10 МБ
`tracing_appender::non_blocking` поверх `app_state::logging::SessionLog`: файл на запуск
(`cogit-<время старта>.log`), после 10 МБ — следующая часть того же запуска, в папке не
больше 10 файлов. Было — `file-rotate`, один `cogit.log` и 2 архива; заменено, потому что
лог нужно было находить по времени запуска (R-159). Суть инварианта не изменилась.
Никаких `println!` и `eprintln!`. Сторонние крейты приглушены через `RUST_LOG`.
*Почему:* синхронная запись в лог на горячем пути — скрытая блокировка; неограниченный лог съедает диск.

<a id="inv-05"></a>
### INV-05 · Ошибки Git пробрасываются без маскировки
При ненулевом коде возврата CLI возвращается `GitCommandError` с полными `command`, `exit_code`,
`stdout`, `stderr`. Замена на «Push failed» или подобное — запрещена.
*Почему:* в `stderr` лежит то, ради чего пользователь и открыл клиент: ссылка на создание PR,
текст pre-receive хука, причина отказа прав.

<a id="inv-06"></a>
### INV-06 · Мониторинг файлов ограничен
Рекурсивный watch корня проекта запрещён. Наблюдаются: `.git/HEAD`, `.git/index`, `.git/refs/`,
`.git/MERGE_HEAD`, `.git/rebase-merge/`, `.git/rebase-apply/` и отфильтрованная рабочая директория.
Исключаются: `.git/objects/`, `target/`, `build/`, `node_modules/`, `dist/`, пути из `.gitignore`.
*Почему:* `.git/objects` меняется тысячами файлов при `fetch`; рекурсивный watch монорепо исчерпывает
хэндлы ОС и генерирует шторм событий.

<a id="inv-07"></a>
### INV-07 · Никаких паник на путях Git
`.unwrap()`, `.expect()` и индексирование срезов без проверки запрещены в коде, работающем
с репозиторием. Detached HEAD, пустой репозиторий, отсутствующий ref, занятый `index.lock`,
битый объект — обрабатываются типизированными ошибками.
*Почему:* паника в Tauri-команде роняет не только операцию, но и доверие к клиенту.
*Исключение:* тесты и константная инициализация.

<a id="inv-08"></a>
### INV-08 · Окончания строк нормализуются перед diff
С учётом `.gitattributes` и `core.autocrlf` текст приводится к `\n` до расчёта дифа.
Фактическое окончание строк хранится отдельно и показывается в статус-баре.
*Почему:* без этого на Windows типичный файл показывается как «изменён на 100%».

<a id="inv-09"></a>
### INV-09 · Тонкий слой Tauri
Тело команды в `src-tauri/src/commands/` — только: достать состояние, вызвать метод крейта,
смапить ошибку. Никакой логики Git, никаких вычислений.
*Почему:* логика в слое Tauri не тестируется без GUI и тянет за собой весь рантайм.

<a id="inv-10"></a>
### INV-10 · Типы IPC генерируются, а не пишутся руками
DTO помечаются `#[derive(specta::Type)]`, файл `bindings.ts` генерируется автоматически.
Ручная правка сгенерированного файла запрещена.
*Почему:* при десятках DTO ручная синхронизация неизбежно расходится и ломается в рантайме.
Исключение — окно графа (R-194): байты колонок, у которых нет DTO. Их раскладку описывает
`app_state::graph_wire`, а синхронность кодировщика и декодера держит общий файл
`frontend/src/lib/graph-wire.golden.bin`, который проверяют тесты обеих сторон. Типы, в которые
окно декодируется (`GraphRow`, `Segment`), по-прежнему генерируются.

<a id="inv-11"></a>
### INV-11 · Единые версии зависимостей через workspace
Все общие зависимости объявляются в `[workspace.dependencies]` корневого `Cargo.toml`,
крейты ссылаются через `{ workspace = true }`.
*Почему:* две версии `serde` или `tokio` в одном бинарнике — это раздутый размер и загадочные
ошибки несовместимости типов.

<a id="inv-12"></a>
### INV-12 · Деструктивные операции обратимы
Перед любой операцией, меняющей историю или рабочую директорию (`reset --hard`, `rebase`, `discard`,
`stash drop`, `branch -D`), состояние фиксируется в журнале безопасности: `ORIG_HEAD`, затронутые refs,
при необходимости — автоматический stash.
*Почему:* цена ошибки в Git-клиенте — потерянная работа; Undo важнее скорости операции.

## 6. Границы, которые легко нарушить

| Соблазн | Почему нельзя | Как правильно |
|---|---|---|
| Вызвать `git` CLI прямо из `src-tauri` | Обходит `GitCommandError` и логирование | Только через `git_engine` |
| Положить общий DTO в `src-tauri` | Крейты не смогут его использовать, появится дублирование | DTO живёт в крейте-владельце данных |
| Кэшировать `gix::Repository` в `AppState` надолго | Держит открытые файлы, изменения извне не видны | Хранить путь и переоткрывать, либо `ThreadSafeRepository` |
| Считать diff в момент рендера строки | Вызов IPC на каждую строку при скролле | Считать пакетно на бэкенде, отдавать готовый `FileDiff` |
| Держать гард `parking_lot::Mutex` через await | Дедлок или блокировка воркера | Взять данные, отпустить гард, потом await |
| Добавить «быстрый» `println!` для отладки | Обходит ротацию и фильтры логов, мусорит в stdout Tauri | `tracing::debug!` с полями |
