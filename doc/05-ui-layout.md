# Cogit — Раскладка и поведение интерфейса

> Что где расположено и как себя ведёт. Визуальные токены — в [06-design-system.md](06-design-system.md),
> шорткаты — в [11-keybindings.md](11-keybindings.md).

## 1. Принципы

1. **Плотность выше воздуха.** Пользователь держит на экране 5 панелей одновременно;
   строка списка — 22–24 px, не 40.
2. **Никаких мастеров.** Любое действие — один клик или один шорткат. Модальные цепочки запрещены.
3. **Состояние видно всегда.** Ветка, ahead/behind, состояние индекса — в статус-баре постоянно.
4. **Ничего не скрывать.** Ошибка Git показывается как есть ([INV-05](01-architecture.md#inv-05)).
5. **Клавиатура равноправна мыши.** Каждое действие тулбара имеет шорткат.

## 2. Сетка главного окна

```text
+----------------------------------------------------------------------------------------------------+
| Cogit  [Repository][Edit][View][Remote][Local][Branch][Query][Tools][Window][Help]         _ □ ✕ |  ← menu 28px
+----------------------------------------------------------------------------------------------------+
| ⭳ Pull ▾ | ⭱ Push ▾ | ⟲ Sync | ✓ Stage | ✗ Unstage | ↺ Discard | ⚑ Stash ▾ | ⑂ Merge | ⎇ Rebase  |  ← toolbar 40px
+------------------------------------+-------------------------------------------+-------------------+
| REPOSITORIES           [Filter]  ✕ | GRAPH & HISTORY                  [Filter]  | FILES (23) Filter |
|                                    |                                           |                   |
|  (дерево проектов и групп)         |  (виртуальный список + Canvas)            |  (файлы коммита)  |
+------------------------------------+                                           |                   |
| REFERENCES                         |                                           |                   |
|                                    |                                           |                   |
|  (HEAD / Branches / Tags / Stash)  |                                           |                   |
+------------------------------------+-------------------------------------------+-------------------+
| DIFF: BencodeParser.cpp (Modified)                       [Side-by-Side ▾] [F6 Next ⭢]              |
|                                                                                                     |
|  (два синхронизированных CodeMirror + сплайны)                                                      |
+----------------------------------------------------------------------------------------------------+
| 🗁 TorrentClient  ⎇ master (= origin) | ↑0 ↓0 | 3 files modified | UTF-8 • LF | ✓ Ready            |  ← status 24px
+----------------------------------------------------------------------------------------------------+
```

Реализация — вложенные сплиттеры: вертикальный (лево / центр+право), внутри левой колонки
горизонтальный (Repositories / References), внутри правой части — горизонтальный (верх / Diff),
внутри верха — вертикальный (Graph / Files).

Под Repositories пристыкована панель **Worktrees** (R-184): свой заголовок с `Add…` и
`Prune All`, свой сплиттер, минимальная высота `--worktrees-panel-min`; включается в
`View ▸ Worktrees Panel` (`Ctrl+7`). Так же под Files стоит Commit Message, у которой строка
управления всегда видна (R-183).

### Правила сплиттеров

- Ширина ручки 1 px, зона захвата 5 px, курсор меняется на `col-resize` / `row-resize`.
- Двойной клик по ручке — сброс к дефолтной пропорции.
- Минимальные размеры: 180 px по ширине, 80 px по высоте. Панель нельзя схлопнуть перетаскиванием
  в ноль — только скрыть через `View`.
- Размеры сохраняются на **перспективу**, а не глобально, и восстанавливаются при запуске
  (`tauri-plugin-store`).
- Размеры пересчитываются в долях, а не в пикселях: при смене разрешения монитора раскладка
  не должна ломаться.

## 3. Панели

### 3.1. Top Action Bar (40 px)

Группы кнопок, разделённые вертикальными линиями 1 px:

| Группа | Кнопки |
|---|---|
| Сеть | `Pull ▾`, `Push ▾`, `Sync` |
| Индекс | `Stage`, `Unstage`, `Discard` |
| Ветвление | `Stash ▾`, `Merge`, `Rebase` |

- Состав и порядок кнопок — `Preferences ▸ Toolbar`; правый клик по тулбару открывает
  этот раздел (R-371).
- Кнопки с `▾` открывают нативное контекстное меню (`tauri::menu`, не HTML-дропдаун).
- Неприменимые действия **disabled**, а не скрыты — положение кнопок не должно прыгать.
- Тултип показывает название + шорткат.
- Справа — индикатор фоновых операций: спиннер + текст текущей операции, кликабельный
  (открывает панель Output).

### 3.2. Repositories (лево-верх)

- Дерево: виртуальная группа → репозиторий → сабмодули (рекурсивно). Только что открытый репозиторий показывает первый уровень сабмодулей сразу (R-546).
- Строка репозитория: иконка со стрелками push (вверх) и pull (вниз) на её углах, слот точки «есть изменения» (у всех строк, чтобы имена стояли по одной вертикали), имя, активная ветка серым; числа — в подсказке. Закрытая строка приглушена (R-351, R-353).
- Сабмодуль с расхождением SHA помечается янтарным маркером: метка положения (`behind`, `not initialized`…) сразу после имени, целиком; ветка или коммит после неё сокращаются (R-544). У каждого узла сабмодуля — те же точка и стрелки, что у строки репозитория, на иконке сабмодуля (R-542).
- Мультивыбор `Ctrl` / `Shift`; групповые действия — `Fetch All`, `Open All`.
- Drag-and-drop перемещает репозиторий между группами.
- Контекстное меню: `Open in Explorer`, `Open in Terminal`, `Fetch`, `Remove from list`, `Rename group`. Пока оно открыто, строка репозитория или сабмодуля, для которой оно открыто, обведена; активный репозиторий не меняется (R-545).
- Фильтр по имени в шапке, `✕` очищает.

### 3.3. References (лево-низ)

Аккордеоны в фиксированном порядке:

| Секция | Содержимое |
|---|---|
| `HEAD` | Текущий коммит, короткий хеш, подсказка о detached |
| `Local Branches (N)` | Ветки, `= origin` при синхронизации, `↑N ↓N` при расхождении |
| `<remote> (N)` | Узел у каждого настроенного remote (`origin`, `upstream`…), даже если с него ещё ничего не получено (`upstream (0)`); его remote-ветки внутри, имя remote с `/` узнаётся по списку remotes; своё меню |
| `Tags` | Lightweight и annotated, разными иконками |
| `Stashes (N)` | `stash@{N}: сообщение` |
| `Lost Commits` | Коммиты из reflog, недостижимые из refs |

**Ключевое поведение:** выбор стэша **мгновенно** показывает его файлы в панели Files
и содержимое в Diff — **без** `stash apply`. Это отдельно оговорено в спеке и является
одним из главных отличий от большинства клиентов.

Двойной клик: по ветке или тегу — то же, что `Check Out` меню, один диалог Checkout ([R-560](12-risks.md)); по папке или группе — свернуть или раскрыть; по stash-у — диалог `Apply Stash` (`Apply`, `Apply & Drop`, `Restore Index`; [R-562](12-risks.md)); по `HEAD` — ничего. Контекстное меню — полный набор операций из M5. `Toggle` — у каждого узла, у заголовка и папки — как их тройной флажок; `Local Branches` — `Add Branch…`, `Tags` — `Add Tag…` (F-550); узел remote — `Push To…` | `Pull`, `Fetch`, `Fetch More` | `Rename…`, `Delete` | `Copy URL` | `Set Depth…`, `Properties…` | `Toggle` (F-551, R-555).

### 3.4. Graph & History (центр-верх)

- **Первая строка** — `Working Tree / Index`, реактивная: показывает число изменённых
  и проиндексированных файлов. Клик по ней переводит Files и Diff в режим рабочей директории.
  С выключенным `Show Working Tree Permanently` (меню настроек графа, F-561) строки нет, пока в
  рабочей копии нет изменений и не прервана операция.
- Далее — виртуализированный список коммитов. Колонки: граф, сообщение, ref-капсулы, автор, дата, хеш.
  Автор, аватар, время и хеш включаются, выключаются и переставляются в
  `Preferences ▸ Graph & History` (там же формат времени, полосы и режимы графа; R-370).
- Линии графа рисуются на `<canvas>` под списком ([INV-03](01-architecture.md#inv-03)),
  подробности — [07-graph-rendering.md](07-graph-rendering.md).
- Ref-капсулы: `[HEAD -> dev]`, `[origin/master]`, `[v1.2.0]`. Цвет по типу ссылки.
- Фильтр в шапке, placeholder `Filter`. Пока в поле есть текст, под шапкой строка переключателей
  `Author`, `Committer`, `Message`, `Refs`, `ID`, `Name`, `Content` — где искать текст (любое
  совпадение); по умолчанию включены все, кроме `Name` и `Content`, выбор сохраняется в настройках
  (`graphFilterFields`, F-560). Префиксы `author:`, `path:`, `oid:`, `since:`, `until:` с
  значением работают как раньше и объединяются с текстом по И.
- Лупа в поле фильтра — меню: `Remember Pattern` (запомнить текст поля), `Forget Pattern`,
  ниже — запомненные шаблоны, новые сверху; выбор подставляет шаблон и сразу фильтрует, `✕` в
  строке или `Delete` забывает его. Список — настройка `graphFilterPatterns`, виден и правится
  в `Preferences ▸ Graph & History ▸ Filter` (F-563).
- Справа от фильтра — «Домой» (Working Tree ↔ коммит HEAD, с другого коммита — Working Tree) и
  «Назад» (к предыдущему выбору в графе этого репозитория; неактивна, пока некуда), F-562.
- Последняя — кнопка меню настроек графа (F-561): `Default` / `Branch` / `Mergeable` / `Varying
  Coloring`, `Graph Preferences…`, `Follow Only First Parent`, `Show Only Selected Branches and Tags`,
  `Include Tracked Remote Branches`, `Show Graph While Filtering`, `Show Working Tree Permanently` —
  те же настройки, что в `Preferences ▸ Graph & History`.
- Мультивыбор двух коммитов (`Ctrl`) сравнивает их в Diff.
- Двойной клик по коммиту (в любом месте строки, линии графа тоже) и по его метке — диалог
  Checkout, как `Check Out` их меню ([R-561](12-risks.md)); по метке stash-а — `Apply Stash`.
- Контекстное меню: `Checkout`, `Create Branch`, `Tag`, `Cherry-Pick`, `Revert`, `Reset to here`,
  `Copy SHA`, `Interactive Rebase from here`.
- Подменю `Bisect ▸` коммита (после группы Reset): `Start…` (диалог: плохой коммит — HEAD, хороший —
  этот коммит), `Mark as Good`, `Mark as Bad`, `Skip`, `Reset`; неприменимое отключено с причиной
  (`no bisect in progress`, `already good`). То же для HEAD — `Branch ▸ Bisect` (`Start…`, `Mark HEAD
  as Good`, `Mark HEAD as Bad`, `Skip HEAD`, `Reset`) и палитра (F-565).

### 3.5. Files (право-верх)

- Таблица: `Name` (иконка вида и имя), `Type` (File, Repository, Binary…), `State` (бейдж), `Path`
  (папка строки) — пути с одной вертикали; сортировка щелчком по заголовку колонки, по
  умолчанию по имени; колонки включаются в `Customise View` ([R-595](12-risks.md)).
- Статусы: `[M]` modified, `[A]` added, `[D]` deleted, `[R]` renamed, `[C]` copied,
  `[U]` unmerged, `[?]` untracked.
- В режиме рабочей директории — две секции: `Staged` и `Unstaged`, с чекбоксами; с выключенным
  `Separate Working Tree and Index` — один список, файл один раз, застейдженное — бейдж в рамке
  ([R-590](12-risks.md)).
- Изменение прав доступа показывается отдельной строкой-примечанием (`100644 → 100755`).
- Переименования отображаются как `old/path.cpp → new/path.cpp` в одной строке.
- Фильтр-маска в шапке (`*.cpp`).
- Кнопки — в заголовках `Unstaged` и `Staged` (`Stage all`, `Unstage all`…), видны всегда; у строк
  файлов кнопок нет ([R-593](12-risks.md)).

### 3.6. Diff (низ)

- Заголовок: путь файла, статус, переключатель режима (`Side-by-Side` / `Unified`),
  навигация по изменениям (`F6` / `Shift+F6`).
- Два `EditorView` CodeMirror 6 с синхронным скроллом.
- Фоновая заливка блоков: зелёная — добавлено, красная — удалено, янтарная — изменено.
- Внутристрочный word-diff подсвечивается более насыщенным оттенком.
- Неизменённые участки сворачиваются в плашку `▲ 48 lines hidden ▲`, клик разворачивает.
- Между панелями — полоса 28 px со сплайнами Безье, связывающими соответствующие блоки. Она же —
  разделитель: линия 1 px посередине в стиле сплиттеров (R-500), перетаскивание меняет долю левой
  колонки кода (20–80 %), `←` / `→` в фокусе — шаг 2 %, `Home` и двойной щелчок — поровну. Доля —
  одна запись настроек `diffSplit`, общая для панели Diff и окна сравнения (R-535).
- Подсветка синтаксиса — Lezer ([INV-01](01-architecture.md#inv-01)).
- Для бинарных файлов — сообщение о размере; для изображений — режимы Side-by-Side, Swipe, Onion Skin.
- В режиме рабочей директории в жёлобе появляются кнопки `Stage hunk` / `Discard hunk`,
  а выделение строк даёт `Stage selected lines`.

### 3.7. Status Bar (24 px)

Слева направо: счётчик команд, упавших или писавших в stderr (треугольник и число, открывает
Output; только пока он не ноль) · текущий репозиторий · ветка и её отношение к upstream ·
`↑N ↓N` · краткая сводка изменений. Справа (R-134): индикатор состояния (`Ready` / операция /
ошибка); пока идёт fetch, pull или push, рядом с ним — `Cancel` (F-529); кодировка и окончания
строк.

Кнопки футера — счётчик и `Cancel` — одна геометрия (`.foot-button`): высота 18 px по центру
полосы, содержимое по центру кнопки. Треугольник счётчика — SVG, как папка репозитория: символ
`⚠` рисовал запасной шрифт со своими высотой и базовой линией, и значок с числом стояли выше
середины (#18, `status-bar-layout.test.ts`).

Кодировка и EOL кликабельны — открывают выбор для текущего файла.

## 5. Модальные окна

### Quick Command Palette (`Ctrl+Shift+P`)

Поиск по всем действиям приложения. Нечёткое совпадение, справа — шорткат.
`Enter` исполняет немедленно. Закрывается по `Esc` или потере фокуса.

### Start Bisect и Bisect Finished

`Start Bisect`: поля `Bad commit` (по умолчанию `HEAD`) и `Good commit` (из меню коммита — он; пусто —
отметить позже в графе), под каждым — найденный коммит (`id` и тема) или «No commit is called …»;
`Start Bisect` неактивна, пока поле не найдено или оба — один коммит. `Bisect Finished` — после
своего шага, закончившего поиск, как в SmartGit: id, автор с датой, сообщение; `Copy ID` слева,
`Continue Bisect` (закрыть, метки остаются) и `Leave Bisect` (`git bisect reset`, основная) справа.

### Find Object (`Ctrl+P`)

Поиск по хешам, веткам, тегам, файлам в текущем коммите. Отдельно от палитры команд,
потому что смешивать объекты и действия в одном списке — путаница.

### Git Error Dialog

Открывается при `CogitError::GitCommand`. Содержит: красную полосу-акцент, выполненную команду
моноширинным шрифтом, код возврата, блоки `stderr` и `stdout` с прокруткой, кликабельные URL,
кнопки `Copy Output` и `Close`. Диалог **не блокирует** остальное приложение — это отдельное
немодальное окно поверх, чтобы пользователь мог сверяться с деревом веток, читая ошибку.

### Output (`Ctrl+Shift+7`)

Нижняя выдвижная панель с историей **всех** запущенных команд Git: время, команда, код возврата,
длительность, свёрнутый вывод. Это инструмент доверия: пользователь всегда может проверить,
что именно Cogit сделал с его репозиторием.

## 6. Отдельное окно File Compare / 3-Way Merge

Независимое `WebviewWindow` (M2), не модальное относительно главного.

Раскладка режима слияния:

```text
+-------------------+-------------------+-------------------+
|  THEIRS           |  BASE             |  OURS             |
|  (incoming)       |  (common ancestor)|  (current)        |
+-------------------+-------------------+-------------------+
|  RESULT (редактируемый)                                   |
|  [◀ Take Theirs] [Take Base] [Take Ours ▶] [Next Conflict]|
+-----------------------------------------------------------+
```

- Четыре редактора CodeMirror; верхние три — только чтение.
- Конфликты нумеруются, навигация `F6` / `Shift+F6`.
- `Ctrl+S` сохраняет результат и помечает файл как разрешённый (`git add`).
- Закрытие с несохранёнными правками — подтверждение.
- Режим простого сравнения (без слияния) использует то же окно с двумя панелями.

## 7. Состояния и обратная связь

| Ситуация | Поведение |
|---|---|
| Загрузка списка | Скелетон-строки, не спиннер по центру — не должно прыгать |
| Пустой результат фильтра | Текст в центре панели + кнопка сброса фильтра |
| Репозиторий не открыт | Центральная заглушка с `Open Repository` и списком недавних |
| Длительная операция | Спиннер в тулбаре + текст; панели остаются интерактивными |
| Данные устарели (событие ФС) | Точка у заголовка панели, если перечитывание идёт дольше 600 мс, + автообновление ([R-591](12-risks.md)) |
| Критическое состояние репо | Баннер над Graph: текст + кнопки по операции (03 §4): `Continue` / `Skip` / `Abort` у rebase, cherry-pick, revert, `git am`; у merge только `Abort` — слияние завершает обычный коммит (R-572); у bisect — `Mark as Good`, `Mark as Bad`, `Skip` для HEAD и `Reset`, текст — что проверять или какой метки не хватает; в конце — первый плохой коммит, `Show Commit` и `Reset` (F-567) |

Никаких блокирующих оверлеев на всё окно: пользователь должен иметь возможность смотреть
на другие панели во время выполнения любой операции.

## 8. Доступность и мелочи, которые заметны

- Фокус виден всегда: обводка 1 px цветом акцента, не `outline: none`.
- Навигация `Tab` по панелям, стрелки внутри списков, `Home`/`End`, `PageUp`/`PageDown`.
- Контраст текста к фону не ниже 4.5:1 для основного текста (палитра это обеспечивает).
- Выделение строки — фон + индикатор 2 px слева, не только цвет: цветом одним пользоваться нельзя.
- Все подписи UI — на английском; локализация в v1.0 не входит.
- Размер шрифта интерфейса настраивается (`View → Zoom`), раскладка не ломается на 125% и 150% DPI.
