# Cogit — Граф коммитов: алгоритм и отрисовка

> Самая сложная часть проекта. Читать перед работой над `crates/graph_engine`
> и `frontend/src/components/graph/`.

## 1. Разделение обязанностей

| Слой | Отвечает за |
|---|---|
| `git_engine` | Обход истории: по дате, но никогда родитель выше потомка (`--date-order`, R-162) |
| `graph_engine` | Раскладка по строкам: узел и сегменты каждой строки. **Чистая функция, без gix** |
| IPC | Чанки строк с уже готовой раскладкой ([INV-02](01-architecture.md#inv-02)) |
| Svelte | Виртуализация списка; левый край сообщения — свой у каждой строки |
| Canvas 2D | Отрисовка видимых строк: сегменты, кольца, стрелки ([INV-03](01-architecture.md#inv-03)) |

Раскладка считается на бэкенде, потому что ей нужно состояние всех полос выше видимого
окна — считать её в JS означало бы передать весь граф в Webview.

## 2. Модель данных

Образец — SmartGit: второстепенные полосы уплотняются, неподвижна только главная (R-161).
Поэтому позиция полосы — её **индекс в списке активных полос этой строки**, и от строки к
строке он меняется. Всё, что нужно нарисовать строку, лежит в самой строке:

```rust
pub struct CommitNode {       // вход; никакой зависимости от gix
    pub oid: String,
    pub parents: Vec<String>,
    pub hidden: Vec<String>,  // родители, которых список не покажет: линия к ним — стрелка
}

pub struct GraphRow {         // выход, одна на коммит
    pub row: u32,
    pub lane: u16,            // колонка узла в этой строке
    pub color: u8,            // для настройки «Coloured branch lines»
    pub kind: NodeKind,
    pub primary: bool,        // узел главной линии
    pub width: u16,           // колонок у верхнего края, узла и нижнего края вместе
    pub segments: Vec<Segment>,
    pub links: Vec<LongLink>, // обрубки длинных связей: номер сегмента и oid другого конца
}

pub struct Segment {
    pub from: u16,            // колонка в начале
    pub to: u16,              // колонка в конце
    pub span: Span,           // Top: верхняя половина строки; Bottom: нижняя; Through: вся строка
    pub primary: bool,        // на главной линии
    pub color: u8,
    pub arrow: bool,          // обрыв стрелкой: родитель вне списка
}
```

Сегменты принадлежат своей строке — ребро не пересекает границу строки, поэтому для
отрисовки экрана нужны только строки на экране. Линии узла — `Top`, приходящие в его центр,
и `Bottom`, уходящие из него. Проходящая полоса — `Through`, только пока идёт прямо; если
сдвигается — пара `Top` + `Bottom` через свою колонку на высоте кольца. Так у всех поворотов
одна форма — полстроки (R-165).

## 3. Алгоритм раскладки

Референс — «Commit Graph Drawing Algorithms» (pvigier), вариант с изогнутыми ветками.

### Состояние

Упорядоченный список активных полос; каждая помнит коммит, которого ждёт. Индекс полосы
в списке и есть её колонка, и он пересчитывается в каждой строке. Курсор переходит из
чанка в чанк, так что потоковая раскладка совпадает с раскладкой всей истории сразу.

### Шаг для коммита `C`

1. **Верхний край** — список, как он пришёл сверху.
2. **Узел.** Все полосы, ждущие `C`, сходятся в нём; узел — в самой левой из них, прочие
   удаляются (сегменты `Top` в центр узла). Если `C` никто не ждал — это вершина ветки,
   её полоса встаёт рядом с полосой, уже ждущей её первого родителя, а без такой — справа.
3. **Родители.** Первый продолжает полосу `C`. Каждый следующий соединяется с полосой,
   которая его уже ждёт, иначе получает новую полосу **сразу справа от узла**, в порядке
   родителей. «Самая левая свободная колонка» не используется: она и давала длинные
   горизонтальные перемычки через половину графа.
4. **Уплотнение.** Полосы, влившиеся в узел, удаляются в этой же строке, и полосы правее
   смыкаются влево. Полоса, которая остановилась в узле (корень, скрытый первый родитель),
   держит колонку до конца своей строки и отдаёт её в начале следующей: иначе соседняя
   полоса въезжала бы под кольцо или под стрелку (R-163).
5. **Три списка.** Верхний край — как пришло сверху; середина (высота кольца) — после того
   как освободились колонки, появилась вершина ветки и влились полосы; нижний край — после
   новых полос родителей. Проходящая полоса рисуется из верхнего индекса в средний
   (`Top`) и из среднего в нижний (`Bottom`); если все три равны — одним `Through`.
   Всё, что приходит, сдвигает соседей в верхней половине, рядом с линиями, входящими в
   узел; всё, что уходит, — в нижней, рядом с линиями, выходящими из него. На высоте кольца
   в колонке узла стоит только он: чужая линия проходит минимум в 3,7 px от кольца.

### Главная линия

Первичный ref — HEAD, иначе `master`, иначе `main`, **из отмеченных в Branches**
(неотмеченный держал бы колонку пустой). Колонка 0 ждёт его коммит, потом цепочку его
первых родителей до корня. Её никто не занимает, не сдвигает и не получает после того, как
линия кончилась. Инвариант проверяется на 300 случайных историях.

### Длинные связи

Связь коммита с родителем длиннее порога `longLinkRows` (по умолчанию 40 строк, `0` —
выключено) не тянется полосой через весь граф, а рисуется двумя обрубками со стрелками, как
в SmartGit: под коммитом — вниз, к родителю (у второго и следующих родителей — с наклоном
вправо), над родителем — наклонная стрелка в узел сверху справа. Колонка между ними не
заводится, её занимают другие полосы, и граф становится уже. Главная линия не рубится;
родитель, которого уже ждёт полоса, соединяется с ней, как обычно; новая полоса родителя под
разрубленной связью первого родителя берёт цвет потомка. Чтобы знать длину связи,
раскладка смотрит на `longLinkRows` коммитов вперёд и отдаёт строки с этим отставанием;
хвост — при завершении обхода (`finish`). У строки обрубки перечислены в `links` с oid
коммита на другом конце (R-330).

### Цвета

Монохромно по умолчанию: главная линия и её кольца — цвет переднего плана темы
(`--graph-main`), всё остальное — один серый (`--graph-line`). Отмеченные в Branches ветки —
своими цветами: от вершины по первым родителям до коммита, который уже на главной линии или
на линии ветки, подсвеченной выше (§5, «Раскраска»). Цвет на полосу — под настройкой
`Coloured branch lines` (выключена); номер цвета даётся полосе при создании и не меняется,
цвет отмеченной ветки поверх него.

### Порядок коммитов

Раскладке нужен порядок, в котором ребра короче всего: по дате, с топологическим
ограничением (`git log --date-order`). Обход в глубину (`--topo-order`, R-140) на
репозитории в 11 053 коммита давал ширину p90 = 27 колонок против 18 по дате (R-162).

Одно исключение: коммит HEAD идёт первым, как только вышли его потомки, — верхняя точка
графа та, на которой пользователь работает, даже если в другой ветке есть коммит новее
(R-164).

Обход свой (`git_engine::graph_walk`), не `rev_walk` gix: очередь по времени коммита, при
равном времени — меньший id. Порядок — функция самой истории, а не того, в каком порядке
пришли вершины, поэтому новый обход может взять время и родителей коммита из прошлого
графа, не читая объект, и получить ровно то, что дал бы обход с нуля (R-301); тексты
строк — в общем кэше по oid.
Время и родители берутся из commit-graph, если он есть, иначе из объекта.
Тему и автора строки граф читает не при обходе, а когда строку просят окном, — один раз на
строку (R-302); раскладке они не нужны. Когда обход закончен, поток `graph-text` дочитывает
тексты всех строк сверху вниз в тот же кэш и останавливается, как только начался новый
обход (R-303).

### Сложность

O(N · L), где L — активные полосы строки. Основное время полной загрузки — чтение
объектов через `gix`, а не раскладка; поэтому у репозитория кэш объектов на 4 МБ (R-162).
Перестройка после отметки ветки или сдвига ссылки читает только новые коммиты, остальные
копирует из прошлого графа; раскладка при этом считается заново целиком (R-301).

## 4. Особые узлы

| Узел | Особенность |
|---|---|
| `Working Tree / Index` | Строка над историей, пунктир от неё к узлу HEAD |
| Любой коммит | Одинаковое полое кольцо; слияние кольцом не выделяется (как в SmartGit). Исключение — stash, у него квадрат (строка ниже) |
| Родитель вне списка | Под узлом короткая стрелка: вниз для первого родителя, вправо-вниз для остальных, чтобы не лечь на линию первого; полоса к нему не тянется |
| Длинная связь | Обрубок под коммитом, как у родителя вне списка, и наклонная стрелка в узел родителя сверху справа; клик по любому концу — переход к другому, tooltip — его короткий хеш и тема |
| Стэш | Только отмеченный в Branches: граф обходит его как `stash@{N}`, у строки фиолетовая метка `stash@{N}` (тултип — сообщение stash-а), узел — квадрат цвета `--status-stash` вместо кольца (F-331, R-232). Неотмеченные stash-и видны только в Branches |

## 5. Отрисовка на Canvas

### Структура DOM

```html
<div class="scroll">                        <!-- единственный скроллируемый контейнер -->
  <div class="viewport">                    <!-- sticky; top: 0; height: 100%; overflow: clip -->
    <canvas></canvas>                       <!-- рисуется кодом по scrollTop -->
    <div class="rows" style="transform: translateY(-scrollTop)">
      <div class="row" style="top: 1234px; padding-left: 58px">…</div>
    </div>
  </div>
  <div class="spacer"></div>                <!-- высота истории минус видимая область -->
</div>
```

Прокручивается только пустой `spacer`: он даёт полосу прокрутки. Строки и холст закреплены
в `viewport` и сдвигаются кодом в одном кадре. Строки, которые прокручивал сам браузер (в
отдельном потоке, раньше кода), при быстрой прокрутке уезжали за отрисованный запас, и на
холсте оставались кольца без текста (R-166). `overflow: clip`, а не `hidden`: слой с
`hidden` браузер может прокрутить сам, например при фокусе на кнопке строки.

Холст шириной с самую широкую строку на экране. У каждой строки свой левый отступ:
сообщение начинается сразу за её последней линией.

### Цикл отрисовки

1. Событие `scroll` → планируем `requestAnimationFrame`, повторные в кадре схлопываются.
   Новый размер холста (высота панели, ширина, `devicePixelRatio`) рисуется сразу, в том же
   кадре, что `ResizeObserver` сообщил его строкам: до перерисовки браузер растягивал бы
   прежний bitmap на новый размер, и линии уезжали бы от текста (`drawsNow` в
   `$lib/canvas-frame`, R-571).
2. В кадре: видимые строки → серые сегменты → цвета веток → главная линия поверх → кольца.
   Цвет и толщину каждого сегмента и кольца даёт одна функция стиля
   (`$lib/graph-style`: `segmentStroke`, `nodeStroke`), слой — порядок рисования.
3. CSS-размер холста — его bitmap, делённый на `devicePixelRatio` (`canvasBox`), и ставится
   там же, где bitmap: картинка показывается пиксель в пиксель, без масштаба, который при
   дробной высоте панели менялся бы с каждым шагом ресайза.

### Раскраска

Раскладка не знает о цветах веток: раскраска — отдельный проход поверх готовых строк
(`graph_engine::paint`, чистая функция). Он идёт по строкам сверху вниз и узнаёт полосы по
колонкам — те же три списка, что в §3: проходящая полоса — верхний край → высота кольца →
нижний край; собственная полоса узла входит в кольцо (у главной линии — сегмент `primary`,
у остальных — самый левый из входящих) и продолжается его первым родителем. Так у каждого
сегмента есть «отрезок полосы»: коммит, из которого он вышел (первый ли это родитель), и
узел, в котором кончается. Длинную связь, разрубленную на два обрубка, проход собирает
обратно по `links`: обрубок над родителем получает полосу обрубка под потомком (у
нескольких потомков — того, чей это первый родитель), а связь — оба своих конца, так что
цвет ветки, ветка коммита и предки с потомками идут через разрыв, как по сплошной линии.
Родитель под разрубленной связью первого родителя (не на главной линии) идёт дальше в
полосе потомка, а раскладка даёт его новой полосе цвет потомка.
Совпадение с раскладкой проверяет тест на 300 случайных историях, с обрубками и без:
узлы одной полосы — цепочка первых родителей, у полосы один цвет раскладки.

Цвет ветки: вершины отмеченных веток, сверху вниз, забирают свои коммиты по первым родителям,
пока не дойдут до истории главной линии или до коммита, забранного веткой выше. История
главной линии — всё, что достижимо из её вершины, в том числе через merge (один проход вниз
по строкам): общая история остаётся своего цвета, и ветка, которую главная линия влила
целиком, не красит ничего (R-570). Линия первого родителя берёт цвет своего потомка,
влитая через merge — цвет коммита, который она приносит; merge, чья линия входит в уже идущую
к тому же родителю полосу, красит свой отрезок сам, а не цветом этой полосы.
Слот палитры — FNV-1a от имени ветки (у `origin/x` — от `x`, чтобы ветка и её копия на
remote совпадали) по модулю 8: цвет не зависит от того, что ещё отмечено, и не меняется
между запусками. Палитра — `--graph-branch-1…8` (дорожки `--c-lane-*`), в каждой из четырёх
тем не ниже 3:1 к фону панели и выделенной строки, попарно различима и отлична от серого —
проверяет `graph-palette.test.ts`.

Раскраску UI берёт окнами, как строки: `graph_overlay` ([04-ipc-contract.md §5](04-ipc-contract.md#5-стриминг-истории)),
блоками по 128 строк (`stores/graph-overlay.svelte.ts`). Пока идёт обход, более поздняя
строка может перекрасить видимую (вершина ниже по списку), поэтому видимые блоки
перезапрашиваются, но не чаще раза в 300 мс. Нечего красить — запроса нет вовсе.

### Резкость на HiDPI

Холст масштабируется на `devicePixelRatio` и пересчитывается при переносе окна на другой
монитор (`matchMedia("(resolution: …)")`). Линии и кольца имеют один центр, поэтому ни
одну толщину не приходится сдвигать на полпикселя (R-114).

### Геометрия

```
LANE_WIDTH      = 16 px   шаг колонок (настройка Lane width, 12–48 px: уже — кольца слипаются)
LEFT_PAD        = 10 px
RING_RADIUS     = 3.5 px  обводка 1.5 px: снаружи 8.5 px
LINE_WIDTH      = 2 px
MAIN_LINE_WIDTH = 2.75 px главная на 0.75 px толще
TEXT_GAP        = 8 px    от последней линии строки до текста
MAX_COLUMNS     = 40      дальше строка обрезается с затуханием
```

Левый край текста строки: `laneX(min(width, MAX_COLUMNS) - 1) + LANE_WIDTH / 2 + TEXT_GAP`.
Но не правее обреза `graphClipX`: правые колонки строки (автор, аватар, время, хеш)
закреплены у правого края, и если полосам не хватает места рядом с ними и 35 символами
темы, область графа обрезается там же, с тем же затуханием (R-331). Высота строки —
`GRAPH.rowHeight` по плотности (20 / 24 / 28 px).

### Кривые

Каждый сегмент — кубическая кривая с вертикальными касательными на обоих концах:

```js
ctx.moveTo(x1, y1);
ctx.bezierCurveTo(x1, (y1 + y2) / 2, x2, (y1 + y2) / 2, x2, y2);
```

Колонка не меняется — вертикаль; меняется — S в пределах своей половины строки (`Top`,
`Bottom`) или всей строки (`Through`). Горизонтальных участков нет. Концы соседних строк
совпадают, поэтому линия идёт без излома.

### Узлы

Кольцо рисуется поверх линий с заливкой тем, что под ним: фоном панели, а на выделенной
строке — фоном панели и поверх фоном выделения. Линии приходят в центр кольца и внутри
не видны.

## 6. Виртуализация списка

- Строки абсолютно позиционированы внутри закреплённого слоя и сдвинуты на `scrollTop`;
  высоту прокрутки даёт `spacer` (`totalRows * ROW_HEIGHT` минус видимая область).
- Рендерятся только видимые строки плюс буфер 10 строк сверху и снизу.
- Высота строки **фиксирована** (`GRAPH.rowHeight`: 24 px, плотность `compact` — 20, `comfortable` — 28). Переменная высота потребовала бы
  измерения каждой строки и сделала бы синхронизацию с Canvas ненадёжной.
- Список сообщает store видимый диапазон (`graph.show`). Недостающие блоки по 128 строк
  приходят через `graph_window`; соседний блок запрашивается заранее, когда до его края
  меньше 64 строк. Фронтенд держит не больше 48 блоков, дальние от экрана вытесняются
  (R-193).
- Клавиатурная навигация меняет `scrollTop` программно; Canvas реагирует тем же путём, что и мышь.
- Граф на экране меняется только на готовый: новый обход, в том числе другого репозитория,
  копится отдельно и показывается, когда покрыл экран или кончился (R-186, R-300). Граф
  другого репозитория открывается с верха списка. Пока на экране строки прежнего
  репозитория, клик по ним ничего не выбирает.
- Раскладка каждого недавно показанного репозитория остаётся в Rust (до 96 МБ на все,
  вытесняется давно не показанный): при возврате к репозиторию с теми же ссылками обхода нет.
- При изменении высоты панели (окно, сплиттер Diff) верхняя строка остаётся на месте: у
  контейнера `overflow-anchor: none` — закреплённый слой высотой с панель иначе сдвигал
  `spacer`, и браузер прокручивал следом, — а `anchoredScrollTop` (`lib/graph-anchor.ts`)
  возвращает прежний `scrollTop`, сдвигая его только у конца истории (#13).

### Синхронизация Canvas и DOM

Единственный источник истины — `scrollTop` контейнера. И строки, и Canvas вычисляют
свою геометрию из него — и применяются в одном кадре, потому что оба двигает код, а не
браузер. Два независимых скролла (отдельно для холста и списка) синхронизировать
надёжно невозможно — этот вариант отвергнут.

## 7. Взаимодействие

| Действие | Реакция |
|---|---|
| Наведение на строку | Подсветка строки (`--state-hover`), кольцо узла заливается тем же цветом; узлы родителей и потомков не выделяются (R-501) |
| Клик по строке | Выбор коммита, загрузка Files и Diff; повторный клик по выбранному возвращает его детали в Diff |
| `Ctrl` + клик | Как обычный клик: выбор переходит. Два коммита сравниваются пунктами `Compare with HEAD` / `Compare with Selected Commit` в меню ветки, тега или stash-а в Branches; второй конец сравнения в графе подсвечен как выбранный (R-501) |
| Наведение на ref-капсулу | Тултип: полное имя; у ветки с remote-двойниками — её имя и имена двойников, у ветки, выписанной в другом worktree, — ещё путь и состояние worktree, у stash-а — `stash@{N}` и сообщение. Даты нет (R-501) |
| Клик правой кнопкой | Нативное контекстное меню |
| Клик по стрелке длинной связи | Прокрутка к коммиту на другом конце и его выбор; tooltip — короткий хеш и тема (R-330) |

Попадание по узлам на Canvas определяется **не** через `getImageData`, а математически:
из координат курсора вычисляется строка и дорожка. Это на порядки быстрее и не зависит
от сглаживания.

## 8. Визуальный Interactive Rebase (M4)

Отдельный режим панели графа, а не отдельное окно.

- Диапазон коммитов для rebase выделяется в графе, режим включается из контекстного меню.
- Строки становятся перетаскиваемыми; порядок меняется drag-and-drop.
- У каждой строки — селектор действия: `pick` / `reword` / `edit` / `squash` / `fixup` / `drop`.
- Панель показывает предпросмотр итоговой истории.
- Подтверждение генерирует `git-rebase-todo` и запускает
  `git rebase -i` с `GIT_SEQUENCE_EDITOR`, подставляющим готовый файл.
- Конфликт во время rebase переводит UI в состояние `Rebase in progress`
  с кнопками `Continue` / `Skip` / `Abort` ([03-git-semantics.md](03-git-semantics.md#4-состояния-репозитория)).

Rebase необратим для незапушенных коммитов, поэтому перед запуском фиксируется `ORIG_HEAD`
и создаётся запись в журнале Undo ([INV-12](01-architecture.md#inv-12)).

## 9. Тестирование

`graph_engine` не зависит от `gix`, поэтому тестируется изолированно, на голых id.

| Сценарий | Проверяется |
|---|---|
| Линейная история | Одна полоса, колонка 0, все сегменты вертикальные |
| Ветка, слитая обратно | Две полосы, пока она жива; главная не сдвигается |
| Полоса кончилась в середине | Полосы правее уменьшают индекс в этой строке |
| Octopus | Новые полосы справа от узла, в порядке родителей |
| Случайные истории (300) | Колонка 0 — только цепочка первых родителей первичного ref, без разрывов |
| Ширина строки | Считается по обоим краям и узлу |
| Родитель вне списка | Стрелка, полоса не тянется в следующую строку; стрелка второго родителя наклонена |
| Случайные истории (300) | Ни одна чужая линия не заходит в колонку узла ни на краях, ни на высоте кольца; под стрелкой пусто |
| Вершина ветки между полосами | Сдвинутая полоса поворачивает в верхней половине |
| Слияние с новой полосой | Сдвинутая им полоса поворачивает в нижней половине, рядом с новой линией |
| Случайные истории (300) | `Through` всегда вертикален: каждый поворот — полстроки |
| Цвета и счёт строк | Совпадают при потоковой раскладке и раскладке сразу |
| Случайные истории (300), раскраска | Полосы по колонкам совпадают с полосами раскладки; своя линия узла — его полоса |
| Отмеченная ветка | Цвет от вершины до главной линии или уже подсвеченной ветки; через неотмеченную — дальше |
| Длинные связи | Рубится только связь длиннее порога; у каждого обрубка есть пара на другом конце; главная линия цела (300 случайных историй); строки, придержанные ради обзора вперёд, приходят по порядку при любых чанках |

Бенчмарк (`app_state::performance`): полная раскладка 50 000 коммитов — не больше
500 мс, первые 200 строк — не больше 300 мс. Замер 23.09.2026: release — 204–210 мс и
8 мс, отладочная сборка — 356–368 мс и 11–12 мс.

## 10. Режимы графа

Каждый режим включается в Preferences и в меню настроек графа справа от фильтра (одни и те же
настройки, F-561), по умолчанию выключен; раскраска — одна из четырёх SmartGit
(`graphColoring`: `Default`, `Branch`, `Mergeable`, `Varying`, R-574). Компонент графа получает
их параметрами (`CommitList`: `firstParent`, `coloring`, …), смысл — `$lib/graph-modes`. Режимы двух видов:
**вид** решает, какие коммиты в графе есть (меняет строки, граф обходится заново), **раскраска**
только красит готовые строки (§5, «Раскраска»).

### Только первые родители

Вид. `CommitQuery.view.firstParent` — то же, что `git log --first-parent` по отмеченным ссылкам:
от каждой стартовой точки обхода только первые родители; merge-коммит остаётся, линии к
влитой ветке нет. Решает сам обход (`git_engine::graph_walk::ByTime`, R-341), до раскладки: коммит
остаётся, если он стартовая точка или первый родитель оставшегося; потомки идут раньше
родителей, так что решение окончательно в момент, когда коммит пришёл, и поток по чанкам
даёт то же, что обход целиком. Оставшиеся раскладываются заново, как будто других не было,
поэтому инварианты §3 держатся без исключений. Родители оставшихся урезаются до первого и в
кэше графа — раскраска видит те же связи, что нарисованы. Отфильтрованный список (поиск)
вид не трогает: он и так плоский (R-51), поэтому смена вида при фильтре поиск не повторяет
(вид возьмёт загрузка, которая снимет фильтр), а треугольников складок в списке нет. Как
режим пришёл из фильтра в обход — R-341.

### Ветка коммита по клику

Раскраска `Branch Coloring`. «Ветка» коммита — его полоса из раскраски (§5): цепочка первых родителей от
точки, где она ответвилась (линия входит в чужой узел), до вершины или до merge, из которого
полоса вышла. Клик по строке выбирает коммит и его полосу; клик по линии в строке
(`laneAt`: колонка и половина строки) — полосу этой линии, пока строка выбрана и граф не
перестроен: номера полос у каждого обхода свои, после нового обхода снова полоса коммита. Полоса
рисуется последним слоем, на 1 px толще главной линии (`FOCUS_LINE_WIDTH`), своим цветом
ветки, если он есть, иначе `--graph-focus`. Считается на фронтенде по номерам полос из
`graph_overlay`, без запроса в Rust на каждый клик (`focusLane` в `$lib/graph-modes`).

### Предки и потомки выбранного

Раскраска. `GraphPaintRequest.ancestryOf` — выбранный коммит; `graph_engine::paint` за два
прохода (вверх от него — потомки, вниз — предки: строки всегда ниже своих потомков) находит
родню, и всё остальное получает бит `PAINT_DIM`. Линия светлая, если родня оба её конца
(у линии к родителю вне списка — если её коммит сам выбранный или предок). Приглушённое
рисуется первым слоем с прозрачностью `DIM_ALPHA` (0,28), цвет ветки при этом сохраняется.
Каждый выбор — новый запрос; пока его ответ в пути, на экране остаётся прежняя раскраска тех
же строк, чтобы граф не мигал серым. Так же после нового обхода того же репозитория (коммит,
fetch): блоки, которые он повторил строка в строку (`kept`, R-301), держат прежнюю раскраску,
пока не пришла своя.

### Mergeable Coloring

Раскраска. `GraphPaintRequest.mergeableOf` — выбранный коммит; `graph_engine::paint` светлым
оставляет его и его предков, которых ещё нет в истории главной линии (`main_history`, как у
цвета веток, R-570), — то, что принёс бы merge выбранного в HEAD; остальное получает
`PAINT_DIM`, как у предков и потомков. Выбран коммит, который главная линия уже содержит, —
приглушено всё. Режим «Предки и потомки» при этой раскраске неактивен: оба приглушают, и
решает Mergeable.

### Varying Coloring

Раскраска: у каждой полосы свой цвет раскладки (`--c-lane-*`), где у ветки нет своего; бывшая
настройка `Coloured branch lines`.

### Сворачивание слитых веток

Вид. `CommitQuery.view.collapseMerged`: у каждого merge, кроме раскрытых (`expanded`), то,
что принёс только он, сворачивается в его строку. Решает `graph_engine::ViewFilter`: коммит остаётся, если
он стартовая точка обхода или родитель оставшегося по линии, которую вид рисует; у
свёрнутого merge рисуется только первый родитель, остальные уходят в его «складку», а
коммит, до которого дошла только складка, считается в ней и отдаёт ей своих родителей
(вложенные слияния сворачиваются вместе с внешним). Линия к родителю, который граф и так
покажет (отмеченная ветка, уже нужный коммит), остаётся. Число коммитов в складке растёт по
мере обхода: `GraphChunk.folds` → кэш графа → `GraphOverlay.folds` для строк окна. В строке
merge — треугольник раскрытия и число; раскрытие перестраивает граф с этим merge в
`expanded`, раскрытые хранятся в `stores/graph-folds.svelte.ts` до переключения репозитория.

### Граф при фильтре

Вид (`Show Graph While Filtering`, `view.filteredGraph`), только при фильтре. Коммиты, которые
фильтр убрал, приходят раскладке в порядке обхода, и `graph_engine::pass_through` переводит
ждавшие их полосы на их первого родителя: совпадение соединяется с ближайшим совпадением вниз
по первым родителям. Обрубков длинных связей в этом режиме нет (R-575).

### Совместимость режимов

Все режимы работают вместе и с цветами отмеченных веток: вид решает, какие строки есть,
раскраска красит то, что осталось, по связям, которые нарисованы. Несовместимых сочетаний
два, они в таблицах `MODE_CONFLICTS` и `COLORING_CONFLICTS` (`$lib/graph-modes`): при «только
первых родителях» сворачивать нечего — слитых веток в графе уже нет; при `Mergeable Coloring`
«Предки и потомки» ничего не добавляет. `conflictingModes(modes)` отдаёт
неактивные режимы с пояснением, `effectiveModes(modes)` — то, что граф применяет на деле;
Preferences читает ту же таблицу через `blockedModes` (`$lib/graph-mode-conflicts`), в
ключах настроек. Режимы приходят в `CommitList` из `GraphPanel` по настройкам `graph*`.
