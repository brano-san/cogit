# F-600 · Состояние файла словами и иконки по состояниям

- [ ] **Колонка State** во всех списках файлов (Files: Unstaged, Staged, единый список, коммит,
      сравнение, stash; окно Commit; Remove Worktree; Log в Investigate) пишет слово, не букву:
      `Untracked`, `Modified`, `Staged`, `Added`, `Missing`, `Removed`, `Renamed`, `Type changed`,
      `Ignored`, `Conflicted (both modified)` и т. д., submodule — `Modified (new commits)` /
      `(dirty)` / `(new commits, dirty)`. Конфликт — цветом `status.danger`, остальное —
      `fg.secondary`. В узкой колонке справа `…`, полный текст в tooltip. Таблица соответствия —
      `03-git-semantics.md`, «Колонка State в списках файлов». Проверить: `git merge` с конфликтом
      `UU`, `DU`, `AA`; файл удалён с диска (`Missing`) и удалён через `git rm` (`Removed` в Staged).
- [ ] **Иконки 16×16** вместо буквенных значков: страница с загнутым углом (submodule — иконка
      репозитория) и оверлей 8×8 в правом нижнем углу: `+` в синем квадрате (Untracked), синий
      `+` (Added), зелёная галочка (Staged), красный `−` (Removed), стрелка (Renamed), белый `!`
      в красном круге и красная заливка (Conflicted); Modified — бледно-красная заливка и красный
      контур, Missing — пунктир, Ignored — 50 %. Цвета — только токены `file.icon.*`; на 100–200 %
      линии остаются в один чёткий пиксель (сетка 16 px, штрихи на половинках). Проверить во всех
      четырёх темах.
- [ ] **Конфликт на иконке репозитория** (панель Repositories): корень с неразрешённым файлом
      получает оверлей `!` и теряет точку «есть изменения» (конфликт важнее Modified); конфликт
      внутри submodule отмечает submodule и все репозитории над ним, пока его ветка дерева
      раскрыта (иначе его пульс не читается). После разрешения оверлей уходит со следующим
      чтением статуса. Пульс закрытого репозитория читает только индекс (`has_conflicts`), без
      сканирования рабочего дерева.
- [ ] Колонка State шире по умолчанию (130 px); сохранённая ширина пользователя не меняется.
