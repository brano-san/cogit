# F-242 · Submodules — ветки дерева, а не список сбоку

- [ ] Submodule раскрывается треугольником внутри своего репозитория; у вложенного submodule есть своя ветка, и так на любую глубину.
- [ ] Рядом с именем видно, на чём он стоит: ветка, либо короткий хеш с темой коммита, либо «not initialised», либо «diverged».
- [ ] Вложенные submodules читаются в момент раскрытия, а не все сразу при открытии репозитория.
- [ ] Двойной клик открывает submodule: все панели показывают его, но в списке репозиториев новой записи не появляется — узел просто помечен как открытый.
- [ ] `Open Repository` с путём того же submodule **добавляет** отдельную запись, и обе работают одновременно.
- [ ] Клик по неинициализированному submodule (и `Open Repository` в его меню) спрашивает, инициализировать ли его; без ответа «Initialise» ничего не меняется, а двойной клик задаёт один вопрос, а не три.
- [ ] Отдельной секции `Submodules` нет: узлы стоят внутри своего репозитория, на своём уровне отступа, подряд с остальными строками дерева.
- [ ] Треугольник есть только у узлов, у которых действительно есть вложенные модули; у листового узла его нет.
- [ ] Два модуля `cmake/cmake-conan` и `cmake/cmake-useful` различимы: при нехватке ширины папка `cmake/` уступает ширину раньше имени и сокращается справа (`cma…cmake-conan`), имя — последним (R-436; усечение только справа, R-243).
- [ ] Раскрытые узлы остаются раскрытыми после перезапуска приложения.
