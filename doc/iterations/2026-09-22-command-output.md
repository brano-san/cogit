# Единое окно вывода git-команд

Задача: при провале и при предупреждении показывать сырой вывод git — так, чтобы
причина («упал такой-то тест в `pre-push`») была видна, а не заменена словом «ошибка».

Ниже — по каждому пункту задания: `уже есть`, `доработал`, `сделал с нуля`.

## Замеры

Лог в 20 000 строк (1.17 МиБ), Node 22, та же машина:

| Что | Время |
|---|---|
| разбор и классификация (`logLines`) | 2.75 мс |
| поиск по всему логу (`findMatches`, 20 совпадений) | 1.77 мс |
| поиск без совпадений | 1.72 мс |

В DOM при этом отдаётся **54 строки** — и столько же при логе в 2 000 000 строк
(`window-box.test.ts`, «asks for the same number however long the log is»).

**Чего я не замерил:** heap вебвью до и после закрытия окна. Для этого нужен профайлер
внутри WebView2, автоматизации для него в проекте нет, а цифра «на глаз из диспетчера
задач» ничего не доказывает. Косвенно: массив строк на 20 000 строк — 1.67 МиБ, узлов
DOM создаётся 54 штуки и они снимаются вместе с окном.

## Решения, принятые самостоятельно

1. **Одно событие вместо трёх** — [R-89](../12-risks.md).
2. **Название операции из командной строки, а не от вызывающего** — [R-87](../12-risks.md).
   Это прямое отступление от текста задания; готов протащить параметр через ~50 мест,
   если нужно именно так.
3. **`Retry` на фронте, а не командой в Rust** — [R-91](../12-risks.md).
4. **Окно + панель истории, а не что-то одно** — [R-89](../12-risks.md).
5. **`Wrap lines` до 5 000 строк** — [R-90](../12-risks.md).
6. **Ёмкость журнала 500 → 100**, как в задании; при двух мегабайтах на запись разница
   между сотней и пятью сотнями — это разница между 200 МиБ и гигабайтом.
