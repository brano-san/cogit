# Бенчмарк и оптимизация: итог — 2026-09-23

Продолжение [чекпоинта](2026-09-23-benchmark-checkpoint.md): там постановка задачи
(приложение A), устройство бенчмарка и первая базовая линия. Метод и команды —
[doc/15-benchmark.md](../15-benchmark.md), решения — R-189…R-200 в
[doc/12-risks.md](../12-risks.md).

## 1. Как мерили

- Release-сборка с оверлеем конфигурации (`npm run bench:build`), свой профиль
  `dev.branosan.cogit-bench`, управление по протоколу DevTools.
- За машиной работал человек: приложение на отдельном рабочем столе Windows (`--hidden`),
  вся работа — на логических ядрах 16–31 (`--cores 16-31`), процесс и его WebView2 — с
  приоритетом AboveNormal. Абсолютные числа поэтому выше, чем на свободной машине, и
  сравниваются только внутри одного режима.
- Фоновая нагрузка отсекается калибровкой до и после каждого замера: занятый замер
  переснимается. Тёплые замеры идут кругами, при разбросе больше 20 % — добор до 30.
- **Каждое изменение — A/B двух сохранённых сборок** в одной сессии: раунды AB BA…,
  12 замеров на вариант, 95 % интервал отношения медиан (бутстреп). «Быстрее» — интервал
  целиком ниже 0,97, «медленнее» — выше 1,03. Нагрузка на машине за день менялась
  (вечерние прогоны заметно быстрее утренних), поэтому разность двух прогонов в разное
  время ничего не доказывает, а отношение внутри A/B — доказывает.
- В каждом замере — самая длинная задача главного потока (`longtask`, от 50 мс).

## 6. Как повторить

```sh
npm run bench:build -- --keep final                         # сборка, копия в target/bench/exes/final.exe
npm run bench -- --hidden --cores 16-31 --exe final         # полный замер, JSON в target/bench/results/
npm run bench -- --hidden --cores 16-31 --ab base,final     # A/B двух сохранённых сборок
node scripts/bench/compare.mjs doc/benchmarks/2026-09-23-baseline.json doc/benchmarks/2026-09-23-final.json
npm run bench -- --hidden --cores 16-31 --check             # падает, если медиана превысила порог (budgets.mjs)
```

Без человека за машиной `--hidden` и `--cores` можно не указывать — числа будут меньше,
пороги рассчитаны на медленный режим.
