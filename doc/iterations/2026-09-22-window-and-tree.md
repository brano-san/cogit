## 2. Пункты 1 и 2: какой коммит и почему решение было неверным

**Коммит `8079819`**, файл `src-tauri/src/lib.rs`:

```rust
window.on_window_event(move |event| {
    // Windows moves the window itself when a monitor is unplugged. A drag
    // cannot put the title bar out of reach, so this only ever undoes that.
    if matches!(event, tauri::WindowEvent::Moved(_)) {
        window_place::settle(&watched);
    }
});
```

Комментарий — и есть ошибка, записанная словами. «Перетаскиванием заголовок за экран не
увести» верно; неверно то, что окно двигает **только** пользователь. Его двигают maximize,
snap, minimize и сама Windows при смене конфигурации мониторов, и на каждое такое движение
обработчик отвечал ещё одним движением. Это не костыль, который надо подпереть, — это
неверная конструкция, и она удалена целиком.

Вторая ошибка — в правиле: «заголовок должен быть ниже верхней границы монитора». Рамка
развёрнутого или пристыкованного окна **намеренно** выходит за рабочую область на десяток
пикселей. Правило объявляло каждое такое окно потерянным. Теперь требуется пересечение
полосы заголовка с рабочей областью на 8 px, что рамку допускает, а заголовок, целиком
ушедший за верх, по-прежнему нет.

и кадр дорисовывался.

| Кейс | Статус |

| перетаскивание между мониторами разного DPI | **не проверено** |

| `Win+↑`, `Win+←`, `Win+→` | **не проверено** |
| двойной клик по заголовку | **не проверено** |
| перезапуск в maximized состоянии | **не проверено** |
| перезапуск после отключения монитора | **не проверено** |
| свернуть и восстановить из панели задач | **не проверено** |
| `Win+D` и обратно | **не проверено** |

логику, а поведение Windows, в которое приложение больше не вмешивается.

## 6. Пункты 21–23 из задачи про дерево: одна причина или разные

**Одна.** Все три — проявления главного потока, занятого боем:

- `Branches (9)` над «Opening repository…» — недорисованный кадр;
- `No repository` и «Opening repository…» в футере одновременно — то же;
- светлая тема в части панелей — **это не баг темы**: приложение было в светлой теме
  целиком (пункт 5 прямо говорит «включил тёмную тему»), а панель графа выглядит тёмной
  потому, что канва рисует свои цвета. Тема доходит до всех компонентов через
  `data-theme` на корне документа, второго документа у главного окна нет.

Заодно расхождение заголовка и тела закрыто конструктивно (R-119), так что даже
недорисованный кадр больше не покажет счётчик над пустой панелью.

## 7. Дерево submodules: структура данных

```
children: Map<ключ, Submodule[]>     ключ — путь от корневого репозитория, "" — он сам
expanded: Set<ключ>                  сохраняется в settings.json по корню репозитория
open:     ключ | null                какой submodule сейчас показан в панелях
```

`moduleRows(children, expanded)` разворачивает это в плоский список строк: обход в глубину,
родитель перед детьми, `depth` растёт на уровень, глубина ограничена шестнадцатью.
Ключ — путь от самого верха (`import/kors/src/tetra/import/dmo`), поэтому раскрытое
состояние переживает обновление и два одноимённых модуля не сливаются.

Строки рисует **`RepositoryList`**, вперемешку со строками репозиториев и групп, с общим
отступом `(глубина репозитория + 1 + глубина модуля) × 12 px`. Отдельной секции
`Submodules` больше нет.

Решения, принятые по постановке:

- открытый submodule помечается так же, как выбранный репозиторий, — выделением и полосой
  слева: заводить второй язык выделения в одном дереве значит заставлять учить два;
- двойной клик по неинициализированному модулю запускает `submodule update --init`,
  потому что открывать там нечего;
- контекстное меню: Open, Init/Update, Show in Explorer.
