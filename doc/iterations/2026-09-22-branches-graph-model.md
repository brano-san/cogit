### Пункт 4.1: где передавался объект тега

`crates/git_engine/src/search.rs`, `tips_for`: отмеченная ссылка резолвилась через
`self.repo.rev_parse_single(rev)`. Для `refs/tags/<аннотированный>` это id **объекта тега**,
а не коммита, — он уходил в `rev_walk` как стартовая точка, и обход падал целиком.
Теперь: `rev_parse_single` → `Object::peel_to_commit` (цепочка тегов разворачивается
полностью); не разыменовалось — ссылка в `SkippedRef`, граф рисуется по остальным.

Проверено по модели:
- метки из **всех** ссылок, без оглядки на отметки — уже было (`refLabels` в `format.ts`);
- метка аннотированного тега на коммите, а не на объекте тега — уже было
  (`into_fully_peeled_id` в `tags()`), теперь закреплено тестом;
- колонка 0 — первые родители `HEAD` — уже было (R-115, тест
  `the_mainline_takes_lane_zero_even_when_it_is_not_the_newest_commit`);
- коммит, достижимый из нескольких ссылок, — один раз: один `rev_walk` на все вершины;
- по умолчанию отмечен только `HEAD` — **было не так** (HEAD + все ветки, R-142), исправлено.

### Пункт 4.2: как хранилось состояние группы

Вычисленное состояние хранилось нигде — `checkState` считал его при каждой отрисовке. Но
у DOM-чекбокса было **своё**: `checked={state === "on"}` — это атрибут, а не владение.
Клик по `−` нативно ставил галочку; код снимал всех детей (старая конвенция «`−` снимает
всех»), вычисленное состояние становилось «пусто», но атрибут был `false` и до, и после —
Svelte ничего не трогал, и в DOM оставался нативно поставленный ✓. Отсюда «✓ над
снятыми детьми». Теперь клик отменяется, а `checked`/`indeterminate` выставляются из
вычисленного состояния всегда. Вторая половина той же ошибки — счёт по строкам экрана, см.
пункт 3.

Конвенция — стандартная: пусто → все, `−` → все, `✓` → никого. Одинаково во всех группах,
включая remote и вложенные папки; состояние папки и группы считается рекурсивно по
листьям поддерева. Попутно: папка `fix/` забирала ветки соседней папки `feat/` — граница
поддерева теперь строго по глубине.

### Пункт 2: как понято требование

В прошлой итерации (R-154) раскрытое сохранялось на репозиторий между запусками. Новое
требование — при запуске всё свёрнуто. Сведено так: раскрытое помнится, пока приложение
работает (вернулся к репозиторию — он как был), но на диск не пишется.

## Тесты

- `git_engine::tips` — 8: аннотированный тег, тег → тег → коммит, тег на дерево (пропущен,
  граф есть, предупреждение), удалённая ссылка, коммит из двух ссылок один раз, отметка
  уже видимой истории ничего не меняет, метка на коммите, `points_to_commit`;
- `app_state::graph` — новый запрос останавливает старый; тег на дерево через `search_graph`;
- `app_state::logging` — 10: имя, части, потолок 10 файлов, старые форматы, чужие файлы;
- фронтенд: `ref-nodes` — трёхпозиционный чекбокс по шагам, свёрнутая группа, вложенные
  папки, неактивные теги, по умолчанию только HEAD; `refs` и `repo-groups` — свёрнуто при
  старте, раскрытое не пишется на диск; `session-memory`, `skipped`.
