## Cogit: перенос чтения на gix — только с доказанным ускорением

Переносим на gix операции **чтения**, которые сейчас идут через процесс `git` или через
медленный путь. Запись не трогаем.

Возможности gix сверяй по docs.rs для версии из `Cargo.lock`, а не по `main`: нужного API в
текущей версии может ещё не быть. Обновлять gix ради пункта — только отдельным решением с
записью в `doc/12-risks.md`.

### Режим работы

- Идёт параллельно с `cogit-tasks-2026-09-24.md`. Пункты 3, 6, 7 — агент gx1, пункт 8 — gx2
  (свои worktree от `tasks/2026-09-24`). Пункты 1, 2, 4, 5 пересекаются с незакрытыми группами
  той партии (1 — g1 #1/#2, 2 — g3 #4, 4 и 5 — g6 #16/#17) и достаются тем же агентам после их
  пунктов.
- Замеры — централизованно после слияния, на простаивающей машине: release, ≥ 10 раундов A/B
  (сборка до пункта против сборки с пунктом), медиана и p95 по сырым прогонам из
  `target/bench/results/*.json`.

### Правило приёмки

Изменение остаётся в коде, только если выполнены **оба** условия. Иначе — откат, замеры
записать в итог.

- [ ] **Скорость доказана бенчмарком** (`doc/15-benchmark.md`): release-сборка, ≥ 10 прогонов
  после прогрева, медиана и p95 до и после на всех применимых наборах (small, medium, large,
  submodules, dirty). Выигрыш засчитывается, если медиана лучше больше чем на разброс между
  прогонами **и** p95 не хуже. Остальные сценарии бенчмарка не замедлились.
- [ ] **Результат совпадает с `git`**: тест паритета сравнивает вывод нового пути с выводом
  консольного `git` на тех же фикстурах. Расхождение — не принимать, даже при ускорении.

Каждый пункт — отдельный коммит. Сначала тест паритета и замер «до», потом правка.

Исключение — пункт 8 (mailmap): это правильность, а не скорость. Для него условие скорости
заменяется на «не замедляет»: сценарии загрузки графа и выбора коммита не хуже «до» в пределах
разброса.

- [x] Список мест, где паритет с `git` не сошёлся, с примером расхождения.
  - Worktrees, порядок: папки `b/one`, `a/two`, `C/three` — git выдаёт `a, b, C` (без регистра при `core.ignoreCase`), у нас было по имени записи `one, three, two` → исправлено (`0a424b3`).
  - Worktrees, папка без `.git`: для `.worktrees/inner` без файла `.git` git пишет `branch refs/heads/inner` и `prunable`, у нас было `branch main` и `missing=false` (папку открывал поиск вверх как основной репозиторий) → исправлено (`b9d41d6`).
  - Защита веток: при неоднозначном имени (тег `upstream/main`) git пишет `remotes/upstream/main`, защита сверялась с этой формой — ветка не считалась защищённой; список совпадает с git, а проверка шаблона — теперь по полному имени (`ffeacc7`).
  - Staged, смена типа файл → symlink: git `T`, у нас `Modified` с новым режимом — оставлено (в `FileStatus` нет такого значения; тест сравнивает `T` как `M`).
  - Worktrees: locked с пропавшей папкой — у нас метка `missing` рядом с `locked`, git не зовёт его prunable — оставлено.
  - Submodules: указатель в индексе, но не закоммичен — git ` ` (берёт из индекса), Cogit `+`/впереди (из HEAD) — оставлено: строка просит закоммитить именно этот коммит.
  - Submodules: `submodule.<name>.active=false` при выписанной папке — git `-`, Cogit «в шаге» — оставлено.
  - Mailmap: git не обрезает пробелы внутри `< a@x >`, разбор gix обрезает — такая строка у git не совпадает ни с одним адресом, у нас совпадает — оставлено.
  - Граф, режим «только первые родители»: `%P` у git перечисляет всех родителей слияния, граф показывает только первого (так рисуется одна линия) — осознанно.
