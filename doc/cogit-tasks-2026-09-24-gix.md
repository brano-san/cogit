## Cogit: перенос чтения на gix — только с доказанным ускорением

Переносим на gix операции **чтения**, которые сейчас идут через процесс `git` или через
медленный путь. Запись не трогаем.

Возможности gix сверяй по docs.rs для версии из `Cargo.lock`, а не по `main`: нужного API в
текущей версии может ещё не быть. Обновлять gix ради пункта — только отдельным решением с
записью в `doc/12-risks.md`.

### Режим работы

- Идёт параллельно с `cogit-tasks-2026-09-24.md`. Пункты 3, 6, 7 — агент gx1, пункт 8 — gx2
  (свои worktree от `tasks/2026-09-24`). Пункты 1, 2, 4, 5 пересекаются с незакрытыми группами
  той партии (1 — g1 #1/#2, 2 — g3 #4, 4 и 5 — g6 #16/#17) и достаются тем же агентам после их
  пунктов.
- Замеры — централизованно после слияния, на простаивающей машине: release, ≥ 10 раундов A/B
  (сборка до пункта против сборки с пунктом), медиана и p95 по сырым прогонам из
  `target/bench/results/*.json`.

### Правило приёмки

Изменение остаётся в коде, только если выполнены **оба** условия. Иначе — откат, замеры
записать в итог.

- [ ] **Скорость доказана бенчмарком** (`doc/15-benchmark.md`): release-сборка, ≥ 10 прогонов
  после прогрева, медиана и p95 до и после на всех применимых наборах (small, medium, large,
  submodules, dirty). Выигрыш засчитывается, если медиана лучше больше чем на разброс между
  прогонами **и** p95 не хуже. Остальные сценарии бенчмарка не замедлились.
- [ ] **Результат совпадает с `git`**: тест паритета сравнивает вывод нового пути с выводом
  консольного `git` на тех же фикстурах. Расхождение — не принимать, даже при ускорении.

Каждый пункт — отдельный коммит. Сначала тест паритета и замер «до», потом правка.

Исключение — пункт 8 (mailmap): это правильность, а не скорость. Для него условие скорости
заменяется на «не замедляет»: сценарии загрузки графа и выбора коммита не хуже «до» в пределах
разброса.

### Пункты

- [ ] **1. Граф: обход через `gix-revwalk` + commit-graph, ленивое чтение коммитов**
  - [ ] Раскладке нужны только топология и даты: родители, даты и поколения — из
    `gix-commitgraph` без распаковки коммитов.
  - [ ] Тема, автор и прочее — распаковываются только для видимых строк и кэшируются.
  - [ ] Коммиты новее файла commit-graph (граф устарел) и репозиторий без commit-graph —
    корректный фолбэк на чтение из хранилища объектов.
  - [ ] Паритет: порядок и родители совпадают с `git log --topo-order --format='%H %P'`.
  - [ ] Замер отдельно на репозитории **с** файлом commit-graph и **без** него.
- [ ] **2. `is_published` и `protecting_refs` без процессов**
  - [ ] Обход от вершин remote-tracking веток с отсечением по номеру поколения вместо
    `git rev-parse --verify` + `git for-each-ref --contains`.
  - [ ] Безопасное умолчание сохраняется: неизвестно, ошибка или таймаут — «опубликован».
  - [ ] Паритет с `git for-each-ref --contains <commit> refs/remotes` на фикстурах: слияния,
    несколько remotes, коммит вне commit-graph.
  - [ ] Если пункт 4 промта оптимизаций уже сделан тем же способом — отметить и пропустить.
- [ ] **3. Список stash через reflog `refs/stash`** вместо `git stash list`.
  - [ ] Паритет с `git stash list --format='%gd %H %gs'`: порядок, индексы, сообщения.
- [ ] **4. «Доступен pull» через `ls-refs` — без fetch и без записи**
  - [ ] Сравнить вершины веток на сервере с локальными remote-tracking ссылками; результат —
    признак для индикатора в Repositories.
  - [ ] Никаких интерактивных запросов учётных данных: только уже настроенные credential
    helpers, запросы и askpass выключены. Нет учётных данных — статус «неизвестно».
  - [ ] Паритет с `git ls-remote --heads <remote>`.
  - [ ] Замер против локального bare-remote (сеть исключена) и против `git ls-remote` как базы.
- [ ] **5. Submodules: список, признак active, рекурсивный статус**
  - [ ] Найти, что из этого сейчас идёт через CLI; перевести только это.
  - [ ] Паритет с `git submodule status --recursive`.
- [ ] **6. Worktrees: список и признак locked**
  - [ ] Найти, что сейчас идёт через CLI; перевести. Признак «устарел» — проверка
    существования пути.
  - [ ] Паритет с `git worktree list --porcelain`.
- [ ] **7. Staged-изменения (HEAD против индекса)**
  - [ ] Индекс из дерева HEAD + сравнение индекса с индексом.
  - [ ] Паритет с `git diff --cached --name-status`.
  - [ ] **Переименования:** в gix отслеживание переименований отличается от git (берётся первый
    подходящий кандидат, имя файла не учитывается). Если на фикстурах с переименованиями
    паритет не сходится — переименования оставить на `git diff --cached -M`, остальное
    принять.
- [ ] **8. Mailmap для имён и email авторов**
  - [ ] Применять `.mailmap` репозитория (и `mailmap.file` / `mailmap.blob` из конфига) при
    показе авторов в графе, Diff, Blame, Investigate.
  - [ ] Аватары запрашиваются по email **после** применения mailmap — у одного человека с
    несколькими адресами одна картинка.
  - [ ] Паритет с `git log --use-mailmap --format='%aN <%aE>'` и `git check-mailmap` на фикстуре
    с `.mailmap`, включая замену только имени и замену имени с email.
  - [ ] Изменение `.mailmap` подхватывается без перезапуска.
